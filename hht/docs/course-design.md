# 講座設計

## 1. コンセプト

受講者は架空の制作会社に入社した新人Webデザイナーです。  
完成見本を最初から作るのではなく、すでに運用中の店舗サイトへ小さな依頼が届きます。  
依頼を読み、対象を特定し、必要なら質問し、修正し、確認を依頼し、安全に公開する流れを繰り返します。

技術と業務を分離しないことが特徴です。  
たとえば価格変更ではHTMLを書き換えるだけでなく、「同じ価格が別ページにもないか」「似た名前の別商品を変えていないか」「税込表示か」を確認します。

各回は「依頼を読む → 判断する → 必要な技術を学ぶ → 制作する → 検証する → クライアントへ返信する」の順で進めます。  
技術を先にまとめて教えるのではなく、その日の仕事を終えるための道具としてHTML・CSSを学びます。

第1回で、編集、ブラウザ確認、練習環境へのデプロイ、バージョン記録、バックアップ、復元までを一度体験します。  
自習時にも同じ手順ですぐ作業を再開でき、失敗しても元へ戻せるため、試行回数と自習効率を上げられます。

全15回は、それぞれの依頼と開始データで独立して取り組めます。  
各回の`lessons/NN/start`には、その回で必要なHTML・CSS・画像・企画を準備します。  
作業場所は`practice/dayNN`とし、他のDAYの完成物を前提にしません。  
カフェ案件の確認・差し戻し・公開、ポートフォリオの企画・仕上げも、それぞれ専用データで始めます。  
架空の参考作品を使う場合は、本人の制作実績と区別します。  
公開先と承認は、その回の対象について講師と確認します。

### ハンズオンを始める前の確認

環境準備や追加演習も、この方針に従います。  
教材の作成・更新では最初に本書と対象の依頼・企画資料を読み、授業では最初に次の5点を学生と確認します。

1. 誰からの依頼で、誰が成果物を見るのか。
2. いま何に困っていて、どういう状態にしたいのか。
3. 何をどう変えるのか。  
   どこは変えないのか。
4. 何を見れば目的を達成したと判断できるのか。
5. 作業前に確認する不明点は何か。

この確認をハンズオンの冒頭に置き、その後に必要な操作・技術を示します。  
「色を変える」「ブランチを作る」などの操作だけを課題の目的にしません。  
終了時には、依頼に対して何ができたか、何で確認したか、何が残っているかを説明させます。  

### 作業記録の環境

全15回でローカルGitを使い、本人用リポジトリの制作ファイルと教材・作業記録を更新します。  

## 2. 学習の柱

| 柱 | 学ぶこと | 主な証拠 |
|---|---|---|
| 受注 | To/CC、期限、承認者、対象、不明点 | 依頼整理票、返信案 |
| HTML | 文書構造、見出し、リンク、画像、表、フォーム | HTML、構造レビュー |
| CSS | カスケード、ボックス、レイアウト、レスポンシブ | CSS、画面比較 |
| デザイン | 目的、情報の優先順位、余白、文字、色、画像 | ワイヤー、意図説明 |
| 品質 | アクセシビリティ、表示、リンク、差分、影響範囲 | チェック記録 |
| 公開 | バックアップ、ステージング、承認、公開後確認 | 公開計画、作業記録 |

## 3. 120分の基本構成

1回120分を、次の流れで構成します。

| 時間 | 内容 |
|---:|---|
| 5分 | 導入講義: 今日学ぶこと、依頼文の違和感 |
| 5分 | 依頼を読む |
| 20分 | 作戦会議: 目的、対象、対象外、質問 |
| 30分 | 依頼に必要なHTML・CSSを試す |
| 10分 | 制作のヒントとデモ |
| 20分 | サイト制作とペア確認 |
| 25分 | 仕上げ、検証、クライアントへの返信 |
| 5分 | 振り返り講義: 講師ならどう判断し、作業するか |

導入講義では正解を先に示さず、依頼文の不足や気になる点へ注意を向けます。  
振り返り講義では完成見本ではなく、講師の判断順序、確認方法、別案を共有します。  
具体的な話題は `docs/instructor-talk-guide.md` を使用します。

## 4. 教え方

- 最初に依頼を見せ、必要性が生まれてから技術を教える
- 変更前に「何を・なぜ・どこまで」を一文で書かせる
- エラーを講師が直さず、開発者ツール、検索、差分から原因を絞らせる
- 見た目だけでなく、キーボード操作、画面幅、代替テキスト、文書構造も確認する
- 公開ボタンを押す能力より、公開してよい状態を判断する能力を評価する
- AIの出力は素材案として扱い、事実・権利・適合性を人が確認する

## 5. 成果物

学生が取り組む課題と完成条件の正本は[学生ワークブック](./student-workbook.md)です。  
本書は授業設計の方針を扱い、課題条件を別管理しません。

### 中間課題（第7〜8回）

フォームと情報の配置を、依頼・制作・検証・報告の流れで確認します。  
具体的な条件はワークブックのDAY 7・8を参照します。

### 最終課題（第14〜15回）

カフェ案件はDAY 11〜13で確認・承認・公開まで行います。  
DAY 14・15は、その制作経験を伝えるポートフォリオを制作・公開します。  
完成条件はワークブックの各回を参照します。

## 6. 合否の考え方

本科目は仕事の流れを覚えることを優先します。  
授業に参加して工程を経験・記録する「参加ルート」と、最終制作で必須基準を示す「制作ルート」のどちらかで合格できます。  
形成的な配点は改善点を見つけるために使い、参加者へ高度な完成度だけを求めません。

## 7. 安全な公開の境界

授業では実在の顧客情報、認証情報、本番サーバーを使用しません。  
学習用環境でも、認証情報をHTMLやスクリーンショットに含めません。  
公開演習は `ISSUES.md` の選択に従います。

## 8. 必要設備

- 最新版の主要ブラウザ
- テキストエディター
- 学校が管理する学習用メール環境
- 画面幅を変更できるPC
- 画像の寸法・圧縮・形式変換ができるツール
- 講師が配布する開始時点のサイト一式
