# 講座設計

## 1. コンセプト

受講者は架空の制作会社に入社した新人Webデザイナーです。完成見本を最初から作るのではなく、すでに運用中の店舗サイトへ小さな依頼が届きます。依頼を読み、対象を特定し、必要なら質問し、修正し、確認を依頼し、安全に公開する流れを繰り返します。

技術と業務を分離しないことが特徴です。たとえば価格変更ではHTMLを書き換えるだけでなく、「同じ価格が別ページにもないか」「似た名前の別商品を変えていないか」「税込表示か」を確認します。

## 2. 学習の柱

| 柱 | 学ぶこと | 主な証拠 |
|---|---|---|
| 受注 | To/CC、期限、承認者、対象、不明点 | 依頼整理票、返信案 |
| HTML | 文書構造、見出し、リンク、画像、表、フォーム | HTML、構造レビュー |
| CSS | カスケード、ボックス、レイアウト、レスポンシブ | CSS、画面比較 |
| デザイン | 目的、情報の優先順位、余白、文字、色、画像 | ワイヤー、意図説明 |
| 品質 | アクセシビリティ、表示、リンク、差分、影響範囲 | チェック記録 |
| 公開 | バックアップ、ステージング、承認、公開後確認 | 公開計画、作業記録 |

## 3. 120分の基本構成

| 時間 | 活動 |
|---:|---|
| 0〜10分 | 前回の振り返り、今回の依頼メールを読む |
| 10〜35分 | ミニレクチャーと短いデモ |
| 35〜45分 | 対象・手順・確認事項を個人で計画 |
| 45〜95分 | 実装演習。途中で一度、隣同士の確認 |
| 95〜110分 | ブラウザ・コード・差分の検証 |
| 110〜118分 | クライアントへの報告文または確認依頼を書く |
| 118〜120分 | 提出、次回予告 |

制作量が多い回はレクチャーを短くし、実装へ振り替えます。メール中心の回は実装時間をロールプレイへ振り替えます。

## 4. 教え方

- 最初に依頼を見せ、必要性が生まれてから技術を教える
- 変更前に「何を・なぜ・どこまで」を一文で書かせる
- エラーを講師が直さず、開発者ツール、検索、差分から原因を絞らせる
- 見た目だけでなく、キーボード操作、画面幅、代替テキスト、文書構造も確認する
- 公開ボタンを押す能力より、公開してよい状態を判断する能力を評価する
- AIの出力は素材案として扱い、事実・権利・適合性を人が確認する

## 5. 成果物

### 中間課題（第7〜8回）

支給された2ページをレスポンシブ化し、文章修正と添付原稿の反映を行います。依頼整理票、質問メール、変更一覧、確認記録を添えます。

### 最終課題（第14〜15回）

複数の更新依頼を優先順位づけし、3ページのサイトを安全に更新します。画像、営業時間、ラストオーダー、対象商品の価格、著作権表示を含みます。ステージング確認依頼と公開後報告まで提出します。

## 6. 安全な公開の境界

授業では実在の顧客情報、認証情報、本番サーバーを使用しません。学習用環境でも、認証情報をHTML、スクリーンショット、提出物に含めません。公開演習は `ISSUES.md` の選択に従います。

## 7. 必要設備

- 最新版の主要ブラウザ
- テキストエディター
- 画面幅を変更できるPC
- 画像の寸法・圧縮・形式変換ができるツール
- 講師が配布する開始時点のサイト一式
- 提出用フォルダーまたはLMS
