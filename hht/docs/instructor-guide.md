# 講師ガイド

## 開講前

1. `ISSUES.md` の回答を確認し、選択済み項目を教材へ反映する。
2. 全PCでブラウザ、エディター、画像変換、提出方法を確認する。
3. 実在しない氏名、アドレス、認証情報だけを使用する。
4. スターターサイトを受講者ごとに複製し、完成版とは分離する。
5. 公開方式に応じて、誤って実在サイトへ接続できない環境にする。
6. 高校生・専門学校生が利用できる学校管理のアカウントと、持ち出してよい素材だけを用意する。
7. AI画像サービスの年齢、利用規約、入力データの扱いを当日に再確認し、実生成できる状態にする。
8. XServer実習では受講者ごとに権限を限定し、本番サイトやメール領域と分離する。

## 授業中の役割

講師は「正しい変更内容を知るクライアント役」と「安全な進め方を支える先輩役」を使い分けます。依頼に不足がある回では、受講者が質問するまで答えを渡しません。ただし、認証情報、個人情報、権利侵害、本番誤公開につながる行動は即時に止めます。

専門用語は最初に日本語で意味を説明し、その後に実務で使われる英語名を併記します。学校用アカウントと個人アカウントを混同させません。

## レビューの順序

1. 依頼と成果物が一致しているか
2. 対象外を変えていないか
3. HTMLの意味と情報順が妥当か
4. キーボード、拡大、小画面で使えるか
5. CSSと画像が意図どおりか
6. 差分、承認、権利、公開記録が残っているか

見た目の好みからレビューを始めると、重大な要件漏れが埋もれます。

## つまずきへの声かけ

| 状況 | 声かけ |
|---|---|
| どのファイルか分からない | 「ブラウザの文言と同じ文字を、対象フォルダーで検索すると何件ですか」 |
| CSSが効かない | 「要素に適用されている規則、打ち消されている規則、読み込み順を見てください」 |
| 全置換しようとする | 「検索結果を種類ごとに分けると、同じ意味の値ですか」 |
| `alt`に迷う | 「画像が見えない人へ、この文脈で失われる情報は何ですか」 |
| すぐ公開しようとする | 「誰が、何を、どの文言で承認しましたか。戻す方法はありますか」 |
| AI出力をそのまま採用する | 「目的、事実、権利、不自然さの4点で、人が採否を説明できますか」 |

## 模擬承認のルール

- 確認URL、変更一覧、未確定事項、期限が揃った依頼だけ承認する
- 「確認しました」ではなく「記載の変更内容で公開可」と明示する
- 一部承認の場合、公開可能な変更と保留を分離させる
- メール送信時点は「依頼中」であり「承認済み」ではない

## 任意の復習・予習

必須宿題は設けません。授業内のハンズオンを優先し、希望者向けに30分以内の任意課題を案内します。

- 副教材の次回該当ページを読む
- 用語集から5語を選び、AIへの指示例を書く
- 次回の依頼メールを読み、不明点を3件以内で考える
- 授業で解決できなかったCSSを最小サンプルで再現する

## 各節の準備

- 第1〜4回: 環境、情報不足のメール、似た文章、HTML構造、CSS競合
- 第5〜8回: ヘッダー、レイアウト、フォーム、配置、アクセシビリティ問題
- 第9〜11回: 画像候補、レスポンシブ、誤字原稿、営業時間・価格・年度
- 第12〜13回: transition、keyframes、キーボード、動き低減
- 第14〜15回: 総合制作、ステージング、バックアップ、意図的な公開不具合

## 検証結果の表記

- `PASS`: 実行し、条件を満たした
- `FAIL`: 実行し、条件を満たさなかった
- `NOT RUN`: 未実行
- `BLOCKED`: 実行を妨げる要因がある
- `NOT APPLICABLE（理由）`: 対象外であることを説明できる

未実行を合格として扱いません。
