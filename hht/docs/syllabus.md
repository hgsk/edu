# 授業レジュメ・シラバス

## 科目名

Webデザイン実習（HTML・CSS）

## 授業時間

- 15回
- 1回120分
- 合計30時間

## どんな授業？

みなさんは今日から、新人Webデザイナーです。  
架空のお店から届く「文章を直して」「写真をもっと目立たせて」といった依頼に挑戦します。  
HTMLとCSSを使って、サイトを直し、確認してもらい、安全に公開するところまで体験します。  
知識を覚えるだけではなく、実際の仕事に近い流れで学ぶ授業です。

## 授業が終わるころにできること

1. ブラウザ・VS Code・ローカルGitを使って、HTML・CSSを書いたり直したりできる
2. 文章の意味に合うHTMLタグと、使い回しやすいclassを選べる
3. Flexbox、Grid、positionを使って、見やすいレイアウトを作れる
4. キーボードでも使いやすいお問い合わせフォームを作れる
5. パソコンでもスマートフォンでも見やすいページを作れる
6. 同じ作品の内容・表示・リンクを確かめ、必要な改善を選べる
7. 依頼された場所だけを正しく直し、確認をもらってから安全に公開できる

## 現行の制作と提出

DAY1〜9は基礎練習、DAY10〜11はポートフォリオのベース制作、DAY12〜15は同じ作品の改善です。  
[共通手順](./workbook/common.md)で教材と作品を分け、全DAYをGitHub PRで提出します。  
後半の外部公開・相互レビュー・発表は任意です。  
評価配点・合格ルートの再解釈は[講師確認事項](../instructor/slide-alignment-20261029.md)で保留しています。

## 本物の仕事に近い進め方

先生は「サイトの修正を頼むお客さま」と「仕事を助ける先輩」の役を担当します。  
みなさんは依頼を読み、分からないことを質問し、サイトを直して、きちんと動くか確かめます。  
最後にお客さまのOKをもらって公開します。

## 1回の授業の進み方

毎回、お客さまから届く依頼メールを開くところから始まります。  
仕事の内容を先に考え、「この依頼には何を覚えればよいだろう？」  
と気づいてからHTML・CSSを学びます。

- 導入講義5分: 「今日は何を学ぶ？  
  この依頼のどこが気になる？」  
  と先生が問いかけます
- 前半55分: 依頼を読む5分 → 作戦会議20分 → 必要な技を試す30分
- 後半55分: 制作のヒント10分 → 制作・ペア確認20分 → 仕上げ・検証・返信25分
- 振り返り講義5分: 「みんなはどうした？  
  先生ならどうする？」  
  を一緒に振り返ります
- 最後に、変更した場所、確認したこと、まだ分からないことをお客さまへ報告します
- DAY10以降は同じ作品を続け、必要な改善を選びます。  
  相互レビュー・発表・外部公開は任意です。

## 成績について

大切なのは、最初から完璧なサイトを作ることではありません。  
「依頼を読む → 考える → 作る → 確かめる → 伝える」という仕事の流れを経験することです。  
合格までの道は2つあります。

- **授業参加ルート:** 授業に参加して、考えたことや作業したことを毎回記録する
- **作品完成ルート:** 最後の作品を完成させ、どこをどう直したか自分の言葉で説明する

授業に参加して取り組んだことも、自分の力で作品を仕上げたことも、どちらも学びとして大切にします。  
従来の配点は参考資料に残し、新構成への評価対応は講師確認まで保留します。

## 必要な環境

- 学校管理のPCまたは授業用PC
- 最新版の主要ブラウザ
- VS CodeとローカルGit
- 受講者ごとのこのリポジトリのコピーまたは作業ブランチ
- 学校が用意した学習用メール環境
- 画像形式変換ができるツール
- 授業用のAI画像生成環境
- 公開演習用の分離された領域

授業は毎回、PCのVS Codeで本人用のローカルGitリポジトリのルートを開いて開始します。  
`hht`などの途中フォルダーだけを開かず、教材、制作ファイル、変更差分、バージョン履歴を同じワークスペースで確認します。

## 安全に学ぶための約束

- 本物の名前、住所、パスワード、仕事の秘密は使いません
- AIが作ったコードも、「何をしているコードか」を確かめてから使います
- お客さま役の先生からOKをもらう前に公開しません
- メール練習では授業用アドレスだけを使い、本物のお客さまには送りません
