# VS Codeで進めるハンズオンの講師用進行

WindowsのVS Codeと導入済みのGitを使い、初回120分で日本語化・教材取得・編集・保存・表示確認・差分確認を一巡します。  
受講者には日本語化の4画面と、日本語表示の操作画面10枚を載せた[ハンズオン手順](./vscode-hands-on.md)を配布し、以後は既存の15回分のDAY教材を使います。

受講者IDは講師が指定します。  
GitHubアカウントの作成やログインを条件にしません。

## 最初に確認するハンズオンの方針

授業準備では、最初に[講座設計](./course-design.md)と受講者用手順の「山本さんからの依頼」を読みます。  
本講座は、依頼を読み、判断し、その仕事を終えるために必要な技術を学ぶ設計です。  
VS Codeの機能紹介だけで始めません。

今回の目的は、学生が自分のPCで練習を続け、次回も同じ成果物から再開できることです。  
支給ページの見出しと色を依頼どおりに変え、既存のリンクと読みやすさを維持し、保存したページを開き直せれば目的を満たします。  
環境準備とGit操作はそのための手段です。

授業の冒頭で、誰が見るか、何を解決するか、何をどう変えるか、対象外、完成条件を学生に説明させます。  
終了時には依頼と成果物を照合し、結果を報告させます。  

## 授業前の準備

1. 学生と同じ権限のWindowsアカウントで、VS Code、`git --version`、Live Server、ブラウザを確認します。  
   授業は日本語表示で進めるため、未導入端末では日本語パックのインストール・表示言語の選択・再起動を試します。  
   拡張機能の導入制限がある場合は事前に管理者へ依頼します。
2. 自分用の教材コピーで、クローンからHTML表示・保存・コミットまで試します。  
   学生の作業場所と衝突しないフォルダーを使います。
3. 教材一式と講師指定の受講者IDを配布します。  
   Gitの初期化と開始状態のコミットを済ませた、受講者ごとの本人用フォルダーを用意します。
4. Gitの表示名とメールの方針を案内します。  
   公開リポジトリなら公開可能なメールまたはnoreplyメールを使わせます。
5. `.vscode/extensions.json`の推奨に `ritwickdey.LiveServer` と `MS-CEINTL.vscode-language-pack-ja` があることを確認します。  
   日本語化前は日本語パックをIDで検索し、教材取得後は `@recommended` からLive Serverを入れます。  
   回線障害に備え教材ZIPを用意し、ZIP経路のGit初期化は講師が補助します。
6. 表示確認と公開演習を分け、段階Cの `hht/hands-on/deployment/server` または受講者別の練習用公開先を準備します。  
   URL・対象パス・反映方法を接続票で指定します。

画面共有には受講者用手順か練習コードを出します。  
`fixtures/emails/`の回答情報、認証情報、学生別の評価は共有しません。  
初回説明には、受講者用ハンズオンのVS Code操作を使います。  
`hht/hands-on/vscode-basics/site`のHTML・CSSは、その操作練習用の原本として保持します。

## 初回120分の進行

![日本語化後のVS Codeと教材フォルダー](../assets/vscode/04-workspace-root.jpg)

この画面を到達確認に使います。  
上部が「ファイル」「編集」「表示」、左側に `README.md` と `hht`、左下にブランチ名が見えることを学生と確認します。  
画像はブランチ作成前の `main` で、作業を始める前に本人のブランチへ切り替えます。

| 時間 | 講師が示すこと | 学生の操作と到達確認 |
|---|---|---|
| 0〜5分 | 山本さんの依頼、目的、対象外、完成条件 | 何をどうしたい仕事なのかを説明する |
| 5〜15分 | 日本語化の4画面 | 日本語パックを入れ、日本語を選択・再起動。メニューを確認 |
| 15〜30分 | DocumentsへのクローンとローカルGitの確認 | hgsk/eduを取得し、Documents/eduを開く |
| 30〜40分 | 推奨拡張と画面構成の画像 | Live Serverを入れ、`hht/hands-on/vscode-basics/site/index.html`を開く |
| 40〜55分 | Live Server起動の画像、h1とtitle | h1の文章を変更し、ブラウザで確認 |
| 55〜65分 | CSSの役割、色の変数 | メインカラーを変更し、表示とコードを対応づける |
| 65〜75分 | 休憩と個別対応 | 未到達者の取得・表示を補助 |
| 75〜90分 | 開発者ツール、幅、拡大、リンク | 幅320・768・1280px、200%拡大、リンクを確認 |
| 90〜110分 | ソース管理の画像で差分確認。全員がコミットと復元 | 2ファイルの変更を説明する。設定エラーを解決してコミットする |
| 110〜120分 | 依頼と結果の照合、保存、再開、報告 | 変更をコミットし、表示を確認する |

操作は「講師が見せる → 学生が行う → 到達確認」の短い単位で進めます。  
早く終わった学生には、title変更やカードの文章修正を追加課題にします。  
全員の初回完了条件を優先し、公開演習は第1回の残り時間または次の授業枠で行います。

## 説明に使う短い言葉

- 「VS Codeは編集する場所、ブラウザは結果を見る場所です。  
  保存してから表示を確認します。」
- 「HTMLで内容と構造、CSSで見た目を変更します。  
  今回触るファイルはこの2つです。」
- 「保存はファイルへの書き込み、コミットは変更の区切りを残す操作です。」
- 「127.0.0.1は自分のPCです。  
  外部への公開と、PC上の表示確認を分けて考えます。」
- 「まず差分を見て、今回変更したファイルだけを記録します。」

## 初回の完了条件

| 確認項目 | PASSの判断 |
|---|---|
| 依頼の理解 | 誰のために何をどう変え、どこを変えないか説明できる |
| 日本語化 | 上部メニューが「ファイル」「編集」「表示」になっている |
| 作業場所 | 自分の教材ルートとブランチを示せる |
| HTMLとCSS | 見出しが「わたしの練習ページ」、メインカラーが指定の青緑になっている |
| ブラウザ確認 | 保存後の表示、各幅、拡大、リンクの結果を示せる |
| 差分と保存 | 指定2ファイルの差分を説明でき、カフェサイトを変更していない |
| 再開と報告 | 保存した練習ページを開き直せて、依頼に対する結果と未確認事項を説明できる |
| 終了 | 作業フォルダーとブランチを控え、再確認後のLive Serverが停止している |

GitHubアカウントやPushの準備待ちにしません。

実施対象のうち未実施はNOT RUN、条件を満たさないものはFAIL、端末権限や回線などで進められないものはBLOCKEDとします。  

## 第1回の公開と復元の演習

既存の第1回で扱うデプロイ・バックアップ・復元は、上の初回練習に続けて実施します。  
初回練習だけで第1回全体を完了と扱いません。  
詳しい公開判定は[演習運営手順](./exercise-operations.md)を使います。

1. `hht/references/cafe-site/index.html`を開き、開始時点を確認します。  
   Git設定済みならコミット、未設定ならPC上の別フォルダーへ開始時点のコピーを保存します。
2. 今回の対象ファイル一覧を決め、`hht/hands-on/deployment/server/staging`へ構成を保って配置します。  
   初回配置では参照するCSS・画像も一覧へ含めます。
3. ステージングの `index.html`をLive Serverで開き、実際のURLと表示を確認します。
4. 模擬公開前の `production` の対象ファイルを日時付きの `backups` へ保存します。  
   初回で対象が存在しない場合は「公開前は未配置」と記録します。
5. 公開判定と承認後に対象だけを `production` へ配置し、その `index.html`を開いて公開相当の表示を確認します。
6. 既存ファイルがある状態でバックアップを取り、講師指定の小さな変更を加えてから、対象だけを戻し表示を確認します。  
   バックアップのない初回状態で復元演習を行いません。

これはPC上の模擬公開です。  
外部URLへの公開は、準備済みの受講者別領域で別途行います。  
実サーバーの接続情報を教材へ保存しません。

## 2回目以降の進行

授業の開始時に、作業フォルダー・ブランチ・未コミット変更を確認します。  
新しい教材を取り込む必要がある場合は、前回の作業を記録してから講師が案内し、全員に一律のPullや変更破棄を指示しません。

その後は[授業パック](../instructor/lessons/README.md)から今日の回を選び、依頼を読む → 計画 → 制作 → 確認を進めます。  

WindowsのPowerShellへLinux向けコマンドをそのまま貼り付けないよう案内します。  
既存のAzure資料を使う回は、WindowsのSSHクライアント、鍵の保存先、アクセス権、転送手段を実機で事前確認してから行います。
