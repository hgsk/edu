### 言葉と構文の読み方：HTMLの最初の1行

**HTML（エイチ・ティー・エム・エル）**は、文章に「見出し」「段落」「リンク」などの役目を付ける書き方です。**CSS（シー・エス・エス）**は色・文字の大きさ・余白・配置を指定する書き方です。**ブラウザ**（ChromeやEdge）はそれを読み、Webページとして表示するアプリです。**エディター**（VS Code）は元の文字を編集するアプリです。

#### ファイル名とフォルダーの読み方

- **ファイル**は保存された1つのデータ。`index.html`はファイル名です。
- **拡張子**は末尾の`.html`や`.css`。HTMLかCSSかなどの種類を示します。`index.html.txt`は同じ名前ではありません。
- **フォルダー**はファイルをまとめる場所。`hht/starter-site/index.html`は「hhtの中のstarter-siteの中のindex.html」と読みます。ここでの`/`は場所の区切りです。
- **ソース**は表示の元になるHTML・CSSなど。ブラウザの画面とソースは同じものではありません。
- **保存**はエディターの変更をファイルへ書くこと。**再読み込み**はブラウザが保存済みファイルを読み直すことです。保存前に再読み込みしても、未保存の変更は出ません。

#### タグと要素を、記号ごとに読む

```html
<h1>一杯から、街の日常をあたためる。</h1>
```

- **`<h1>`**（エイチ・ワン）は開始タグ。「ここから大見出し」と示します。`h`はheading（見出し）、`1`は見出しの階層です。
- **`<`と`>`**はタグの名前を囲む半角記号。画面にそのまま出したい本文とは区別されます。
- **間の日本語**は内容。今回編集するのは、ここだけです。
- **`</h1>`**は終了タグ。`/`が付くと「ここでh1を終える」です。開始・終了で名前をそろえます。
- **要素（ようそ）**は、開始タグ・内容・終了タグを合わせたまとまりです。「タグ」と「要素」は関連する言葉ですが、指す範囲が違います。

`<h1>`だけを書いて終わりにしたり、終了を`</p>`にしたりすると、囲む範囲が意図とずれます。タグの記号は半角で書き、日本語の本文は日本語で構いません。

#### ページ全体の中で、今どこを編集している？

```html
<!doctype html>
<html lang="ja">
  <head>
    <meta charset="utf-8">
    <title>カフェのホーム</title>
  </head>
  <body>
    <h1>一杯から、街の日常をあたためる。</h1>
  </body>
</html>
```

これは**構造を読むための短い例**です。既存のページ全体をこの例で置き換える課題ではありません。

- **`<!doctype html>`**はHTMLの文書であることをブラウザへ伝える宣言。本文を囲むタグではありません。
- **`html`**は文書全体。`lang="ja"`は「この文書の言語は日本語」という追加情報です。
- **属性（ぞくせい）**は、開始タグに書く追加情報。`lang`が属性名、`=`の右の`"ja"`が値です。**`=`は属性名と値を結び、`" "`は値の範囲を囲む**と読みます。
- **`head`**は文書の設定。**`title`**はブラウザのタブの名前。画面内の見出し`h1`とは別です。
- **`meta charset="utf-8"`**は文字の読み取り方を指定します。文字化けを防ぐための設定です。`meta`には終了タグを書きません。
- **`body`**はページに表示する内容。今日はこの中の`h1`を探します。
- 行頭の空白は**インデント**。囲む関係を人が読みやすくするために字下げしています。

#### 今日出てくる操作の言葉

- **URL（ユー・アール・エル）**はブラウザで開く場所を示す文字列。`http://localhost:8000/`の`localhost`は今使っているPC、`8000`は接続口の番号（**ポート**）です。別の人のPCから同じURLを開いても、自分のファイルは見えません。
- **HTTPサーバー**は、ブラウザから求められたファイルを渡すプログラム。下のSTEP 2で起動します。`python -m http.server 8000 --directory hht/starter-site`は「PythonでHTTPサーバーを起動し、8000番でstarter-siteを配る」と読みます。これはHTMLではなくターミナルへ入力する命令です。
- **デプロイ**は確認・公開先へ対象ファイルを配置すること。**staging（ステージング）**は本番に出す前の確認場所。今回の模擬公開はPC内の練習で、インターネットへ一般公開したことにはなりません。
- **バックアップ**は戻すための保存コピー。**バージョンID**はどの保存状態かを区別する名前。**復元**は保存した内容へ戻す操作です。Gitなしでは保存フォルダー名をIDにできます。
- **From／To／CC**はメールの差出人／宛先／情報を共有する相手。受領返信は「依頼を受け取りました」と伝える返信です。

ここまでは説明です。実際の編集は次のSTEP 1から順に行います。

### 例を分解して読む：必要な項目から確認する

ここは、今日の実習に出てくる言葉を1つずつ読むための参照欄です。全部を追加する作業一覧ではありません。最初は使う項目だけを読み、つづり・記号・意味・画面の変化を対応させます。実習へ進むときはこの欄の後の手順へ戻ります。

#### 読み取り例：見出しの囲み — h1

**何の言葉？** 見出しとしての役目を持たせるための要素です。開始と終了のタグに挟まれた文字が内容です。タグそのものは通常のページ本文へそのまま表示されません。

```html

```

**まず外側を読む：** `<`から最初の`>`までが開始タグです。`h1`という名前で、このまとまりの役目をブラウザへ伝えています。見た目の色や大きさをここで直接決めるとは限りません。CSSのセレクターから選ばれ、見た目が付く場合もあります。

- この短い例では属性を省略しています。`h1`は要素名です。必要な属性がある実際のファイルでは、名前と値を1組ずつ読みます。

**どこまでが1つ？** `</h1>`はこの要素の終了です。開始と同じ名前を使い、先頭に`/`を付けます。開始と終了の間の内容が、この要素のまとまりです。 見本に内容の位置を示すコメントがある場合は、コメント自体を提出する文章として使う意味ではありません。元のファイルのどの内容を残すかを、依頼に合わせて確かめます。

**画面と照合する：** 見出しの内容が画面へ表示されることを確認します。設定用の要素は本文画面へ直接文字が出ない場合もあるので、要素の目的に合う場所を見ます。画面上で変化がないことと、HTMLに役目がないことは同じではありません。

**この例で間違いやすいところ：** タグの記号ごと画面に出た場合は、ファイルをHTMLとして開いているか、文字参照として書いていないかを見る。属性の値をタグの外へ書いたり、本文と設定をまとめて書き換えたりしないようにします。変更前を残すと、どの記号や文字を変えたか比べられます。

### STEP 1　作業場所と依頼を確認する

**このSTEPで行うこと：教材ルートと依頼**

VS Codeの左側の一覧でREADME.mdとhhtを探します。hhtの中にstarter-siteとsubmissionsがあるか展開して確認します。依頼のFrom／To／CCを読み、自分が何を返す役なのかメモします。

### 完成条件・提出するもの

**入力:** リポジトリ、最初の依頼メール、練習用公開先（配布されている場合。なければpractice-server/staging）

**完成物:** 開発者ツール確認メモ、DAY 1練習用のHTML変更、確認URL、開始・変更後のバージョンID、復元記録、WORKLOG.md、受領返信

**完成条件:**

- VS CodeまたはCodespacesでリポジトリのルートを開き、自分用のコピーまたは作業ブランチを使っている
- Elementsでh1を選び、Stylesで適用中のCSSを1つ確認している
- 375px幅とConsoleを確認し、開発者ツールの一時変更が再読み込みで戻ると説明できる
- 開始時点と変更後のバージョンIDを記録している
- DAY 1練習用のHTML変更がローカルと練習公開先の両方に表示される
- 練習用URLが配布されていない場合、practice-server/stagingを模擬公開先としてブラウザ表示している
- ソースを開始時点へ一度戻し、変更後へ戻せる
- 模擬公開を使った場合、practice-server/backupsの復元用コピーから公開側も一度戻している
- 接続情報を推測していない。パスワード、秘密鍵、Cookie、個人用トークンを記録・提出していない。認証情報を含まない実際の確認URLだけを記録している
- hht/submissions/day-01/WORKLOG.md に確認URL、開始・変更後バージョンID、復元結果を残している

**証拠:** 開発者ツール確認メモ、375px幅の画面、Consoleのエラー有無、実際に開いた練習用URLまたは模擬公開URL、開始・変更後バージョンID、復元前後の画面、WORKLOG.md

**困ったとき:**

- 外部の練習サーバー情報がない場合は、URLや認証情報を作らず、practice-server/stagingを模擬公開先にする
- 提出はPRで行い、開始と変更後のコミットをWORKLOGへ記録する。手元の保存コピーは補助バックアップとして残せる
- ローカルHTTPサーバーで「Address already in use」と出た場合は、8001など空いているポートへ変更し、ブラウザ側も同じ番号にする
- CodespacesではPORTSに表示されたForwarded Addressを使い、URLを手入力で推測しない
- どの方法でも「変更前へ戻せること」「ブラウザで確認できること」「復元結果を記録すること」は省略しない

**追加チャレンジ:** 「作業を開く → 編集 → 確認 → バージョン記録 → 練習公開」を、次回の自分が迷わない5行でWORKLOG.mdに追記しよう。
