### 言葉と構文の読み方

**フォーム**は入力欄のまとまり。HTMLの見た目を作ることと、メール送信などの処理を作ることは別です。今回は入力と操作の確認までです。

```html
<form>
  <label for="contact-name">名前（必須）</label>
  <input id="contact-name" name="name" type="text" required>
  <label for="contact-message">問い合わせ内容</label>
  <textarea id="contact-message" name="message"></textarea>
  <button type="button">確認用ボタン（送信しません）</button>
</form>
```

- **`form`**はフォーム全体、**`label`**は入力欄の説明。`for`の値と入力欄の`id`を一致させると、説明をクリックして欄を選べます。
- **`input`**は空要素の入力欄。`type="text"`は1行の文字入力、`type="email"`はメール形式の欄。**`name`**は送るデータの項目名で、説明文の代わりにはなりません。
- **`required`**は必須という真偽属性。付いていれば有効です。`required="false"`としても無効にはなりません。必須という説明も文字で付けます。
- **`textarea`**は複数行の欄。`input`と違い終了タグがあります。**`button type="button"`**は送信しないボタンです。
- **`checkbox`**は複数選択、**`radio`**は同じ`name`の中から1つ選択。**`select`と`option`**は選択リストとその選択肢。**`fieldset`と`legend`**は関連する欄のグループとその見出しです。
- **`placeholder`**は未入力時の例。入力すると消えるためlabelの代用にしません。**`action`**は送信先、**`method`**は送信方法。今回は実際の送信先を設定しません。

ここは書き方の説明です。既存ファイルを全部消して貼り替えず、下の実習で対象を確認してから使います。

### 例を分解して読む：必要な項目から確認する

ここは、今日の実習に出てくる言葉を1つずつ読むための参照欄です。全部を追加する作業一覧ではありません。最初は使う項目だけを読み、つづり・記号・意味・画面の変化を対応させます。実習へ進むときはこの欄の後の手順へ戻ります。

#### 読み取り例：margin-bottom（マージン・ボトム）

**何の言葉？** 要素の下側の外側余白です。フォームの項目どうしを離して読み取りやすくする用途があります。下側のpaddingは箱の内側なので位置関係が異なります。

```css
.contact-field {
  margin-bottom: 1rem;
}
```

**上から順に読むと：** 「.contact-fieldで選ぶ要素に、margin-bottomという項目を、1remという値で指定する」です。どの要素を選ぶかと、その要素の何を変えるかを別々に読みます。セレクターとプロパティ名は同じ役目の言葉ではありません。

- `.contact-field`は**対象**です。自分のHTMLにある要素名・class・idと対応するかを先に調べます。見本の名前を写すだけでは、存在しない対象には表示の変化が出ません。
- 開く`{`から閉じる`}`までが、この対象へ書く**規則の本体**です。前後にある別の要素への規則を巻き込まないように、区切りを追います。
- `margin-bottom`が**プロパティ**、`:`の後の`1rem`が**値**です。項目名と値を逆に書きません。HTMLの属性のように`=`で結ぶ書き方でもありません。
- `;`はこの宣言の終わりです。1つの規則へ次の項目を書くときも、宣言の区切りを保ちます。日本語の本文と違って、記号の種類が読み取りに関わります。

**表示との対応：** 正しく当たる条件なら、隣の項目との間が広がることを確認します。コードにこの行があるというだけでは、最終的にこの値が採用された証拠にはなりません。選んだ要素のStylesで、採用・上書きの状態も対応させます。

**比べると理解しやすいこと：** どの要素へ余白を付けると説明と入力欄が同じ組に見えるかを比較する。変更は作業用コピーで1項目ずつ行い、見る場所と画面幅をそろえて比較します。変化がなければ、まず元の状態との違いを言葉にします。

**この例で間違いやすいところ：** 項目の組が離れ過ぎるならlabelと入力欄ではなく、1項目のまとまりへ指定しているかを見る。全角記号に変わっていないか、値に必要な単位やかっこが残っているかも確かめます。原因が分からない間に別の場所へ同じ宣言を大量に追加せず、実際の対象と採用元を追います。

**理解の確認：** 「この指定は誰に当たる？」「どの項目を変える？」「画面のどこを見れば分かる？」を、この例の対象・項目・結果の言葉で説明してみましょう。説明のための読解例なので、この規則をそのまま全ページへ追加する課題ではありません。実際に変える範囲は今日の依頼と実習を使います。

#### 読み取り例：入力欄全体 — form

**何の言葉？** 入力項目をまとめる要素です。送信処理のあるフォームもありますが、今回の課題は入力画面と操作の確認。formがあるだけでメールが届くわけではありません。

```html
<form>
  <!-- この要素の内容が入ります -->
</form>
```

**まず外側を読む：** `<`から最初の`>`までが開始タグです。`form`という名前で、このまとまりの役目をブラウザへ伝えています。見た目の色や大きさをここで直接決めるとは限りません。CSSのセレクターから選ばれ、見た目が付く場合もあります。

- この短い例では属性を省略しています。`form`は要素名です。必要な属性がある実際のファイルでは、名前と値を1組ずつ読みます。

**どこまでが1つ？** `</form>`はこの要素の終了です。開始と同じ名前を使い、先頭に`/`を付けます。開始と終了の間の内容が、この要素のまとまりです。 見本に内容の位置を示すコメントがある場合は、コメント自体を提出する文章として使う意味ではありません。元のファイルのどの内容を残すかを、依頼に合わせて確かめます。

**画面と照合する：** 入力項目が1つのフォームとしてまとまることを確認します。設定用の要素は本文画面へ直接文字が出ない場合もあるので、要素の目的に合う場所を見ます。画面上で変化がないことと、HTMLに役目がないことは同じではありません。

**この例で間違いやすいところ：** 実在の送信先を仮に書いて動作確認せず、今回の対象外を記録する。属性の値をタグの外へ書いたり、本文と設定をまとめて書き換えたりしないようにします。変更前を残すと、どの記号や文字を変えたか比べられます。

- **`name="topic"`**は、属性名`name`と値`topic`の組です。`=`は両者の区切り、前後の半角の二重引用符は値の範囲。属性は開始タグの`>`より前へ置きます。

**どこまでが1つ？** `</select>`はこの要素の終了です。開始と同じ名前を使い、先頭に`/`を付けます。開始と終了の間の内容が、この要素のまとまりです。 見本に内容の位置を示すコメントがある場合は、コメント自体を提出する文章として使う意味ではありません。元のファイルのどの内容を残すかを、依頼に合わせて確かめます。

**画面と照合する：** リストから選択肢を選べることを確認します。設定用の要素は本文画面へ直接文字が出ない場合もあるので、要素の目的に合う場所を見ます。画面上で変化がないことと、HTMLに役目がないことは同じではありません。

**この例で間違いやすいところ：** optionをselectの外へ置いていないか、選択肢ごとのvalueを確認する。属性の値をタグの外へ書いたり、本文と設定をまとめて書き換えたりしないようにします。変更前を残すと、どの記号や文字を変えたか比べられます。

**HTMLとして読む順序：** 最初に要素名、次に開始タグの属性、次に内容、最後に終了を読みます。内側に別の要素があれば同じ順序を繰り返します。字下げをそろえるのは、この囲む関係を見つけやすくするためです。画面で改行されるかどうかは、要素とCSSの表示の指定も関係します。

**理解の確認：** 「何の役目の要素か」「値や本文はどこか」「どの場所で結果を確かめるか」を、この例を指しながら説明してみましょう。読み方を理解するための見本であり、既存ページをこの短い例だけで置き換える課題ではありません。使うファイルと変更範囲は今日の実習の案内を優先します。
