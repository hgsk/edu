### 言葉と構文の読み方

**ヒーロー画像**はページ冒頭の大きな画像。**WebP（ウェッピー）／AVIF（アビフ）**は画像の保存形式。**ピクセル寸法**は縦横の点の数、**容量（KB）**はファイルのデータ量で、別の値です。

```css
.hero {
  background-image: url("../images/hero-cafe.webp");
  background-size: cover;
  background-position: center;
}
```

- **`url(...)`**は使うファイルの場所。CSSファイルから見た相対パスなので、`css/style.css`から画像へは`../images/...`です。
- **`cover`**は領域を埋めるように拡大・縮小する指定。縦横比によって画像の端は切れます。**`center`**は中央を基準に配置する値です。
- **`alt`**はHTMLの`img`の代替テキスト。CSSの背景画像にはaltを書けないため、大切な情報は本文にも残します。
- **出自**はどこから来た素材か、**利用条件**は何に使ってよいか。形式を変えても利用条件は消えません。

ここは書き方の説明です。既存ファイルを全部消して貼り替えず、下の実習で対象を確認してから使います。

### 例を分解して読む：必要な項目から確認する

ここは、今日の実習に出てくる言葉を1つずつ読むための参照欄です。全部を追加する作業一覧ではありません。最初は使う項目だけを読み、つづり・記号・意味・画面の変化を対応させます。実習へ進むときはこの欄の後の手順へ戻ります。

#### 読み取り例：background-image（バックグラウンド・イメージ）

**何の言葉？** 背景へ画像を読み込みます。パスの基準はこの宣言を書いたCSSファイルです。HTMLから見たパスとは違うのでcssフォルダーから1つ上へ戻ります。

```css
.hero {
  background-image: url("../images/hero-cafe.webp");
}
```

**上から順に読むと：** 「.heroで選ぶ要素に、background-imageという項目を、url("../images/hero-cafe.webp")という値で指定する」です。どの要素を選ぶかと、その要素の何を変えるかを別々に読みます。セレクターとプロパティ名は同じ役目の言葉ではありません。

- `.hero`は**対象**です。自分のHTMLにある要素名・class・idと対応するかを先に調べます。見本の名前を写すだけでは、存在しない対象には表示の変化が出ません。
- 開く`{`から閉じる`}`までが、この対象へ書く**規則の本体**です。前後にある別の要素への規則を巻き込まないように、区切りを追います。
- `background-image`が**プロパティ**、`:`の後の`url("../images/hero-cafe.webp")`が**値**です。項目名と値を逆に書きません。HTMLの属性のように`=`で結ぶ書き方でもありません。
- `;`はこの宣言の終わりです。1つの規則へ次の項目を書くときも、宣言の区切りを保ちます。日本語の本文と違って、記号の種類が読み取りに関わります。

**表示との対応：** 正しく当たる条件なら、heroの背景に画像が出ることを確認します。コードにこの行があるというだけでは、最終的にこの値が採用された証拠にはなりません。選んだ要素のStylesで、採用・上書きの状態も対応させます。

**比べると理解しやすいこと：** img要素として表示する場合と、代替テキストの持ち方や切れ方が異なる。変更は作業用コピーで1項目ずつ行い、見る場所と画面幅をそろえて比較します。変化がなければ、まず元の状態との違いを言葉にします。

**この例で間違いやすいところ：** 画像が出なければファイルの有無、拡張子、CSSからの相対位置を確認する。全角記号に変わっていないか、値に必要な単位やかっこが残っているかも確かめます。原因が分からない間に別の場所へ同じ宣言を大量に追加せず、実際の対象と採用元を追います。

**理解の確認：** 「この指定は誰に当たる？」「どの項目を変える？」「画面のどこを見れば分かる？」を、この例の対象・項目・結果の言葉で説明してみましょう。説明のための読解例なので、この規則をそのまま全ページへ追加する課題ではありません。実際に変える範囲は今日の依頼と実習を使います。

### 実習の進め方

### STEP 1　質問を考える

**このSTEPで行うこと：画像要件**

依頼の「インパクト」を、誰へ何を伝えたいのかへ言い換えます。被写体、見せたい内容、文字を置く範囲、避けたい表現を分けて質問します。

**できたかの見分け方：** 画像を選ぶ判断軸と確認待ちが記録されることを、編集画面だけでなく必要な表示・操作で確かめます。「操作した」ことと「期待した結果を見た」ことを分けて考えます。

**そこで止まったとき：** 色を派手にするだけで依頼を満たすとは限りません。写真の内容とページの目的、載せてよい素材かを先に確かめます。 原因を調べる間は、最後に確かめられた状態を残します。分からない箇所を全部消してやり直すより、今のファイル・今のSTEP・出ている表示を特定すると相談しやすくなります。

**記録の考え方：** このSTEPで実際に見た結果を、今日の制作メモまたはWORKLOGの該当項目へ短く残します。例の成功文を先に写して完了扱いにしません。結果が違った場合も、どこまで進めたかを残せば次に再開する手がかりになります。


依頼者に確認したいことを考えます。

例:

- コーヒーを目立たせたいですか
- お店の雰囲気を目立たせたいですか
- 写真の上に文字を置きますか
- 避けたい表現はありますか

### STEP 5　選んだ理由を報告する

**このSTEPで行うこと：採用理由の報告**

形式・寸法・容量の変化、利用条件、どの候補をなぜ採用したかを報告します。見た幅も添え、未確認の利用範囲があれば公開前に確認します。

**できたかの見分け方：** 素材の根拠と表示結果が採用理由につながることを、編集画面だけでなく必要な表示・操作で確かめます。「操作した」ことと「期待した結果を見た」ことを分けて考えます。

**そこで止まったとき：** 「軽くしました」だけでなく、元と出力の実測値を書きます。容量の小ささだけで採用し、読めないほど画質を落とさないようにします。 原因を調べる間は、最後に確かめられた状態を残します。分からない箇所を全部消してやり直すより、今のファイル・今のSTEP・出ている表示を特定すると相談しやすくなります。

**記録の考え方：** このSTEPで実際に見た結果を、今日の制作メモまたはWORKLOGの該当項目へ短く残します。例の成功文を先に写して完了扱いにしません。結果が違った場合も、どこまで進めたかを残せば次に再開する手がかりになります。


「こちらの方がインパクトがあります」だけではなく、

- 何が見やすいのか
- 何を目立たせたのか
- スマホでどう見えるのか

まで説明します。
