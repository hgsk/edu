### 言葉と構文の読み方

**レスポンシブ**は画面幅などに合わせて表示を調整する設計。**ブレークポイント**はCSSを切り替える境目。**メディアクエリー**はその条件を書く仕組みです。

```css
.menu-grid {
  grid-template-columns: 1fr;
}
@media (min-width: 48rem) {
  .menu-grid {
    grid-template-columns: repeat(2, 1fr);
  }
}
```

- **`@media`**は「この条件に合うときだけ中のCSSを使う」。**`min-width`**は幅が指定値以上という条件です。48remは基準文字が16pxなら768px相当です。
- 外側の`{ }`は条件に合うCSSのまとまり、内側は通常のCSS規則。閉じる`}`も2つあります。
- **`max-width: 100%;`**は親の幅を超えない上限、**`height: auto;`**は高さを自動にする指定。画像の比率を保つ用途に使います。
- 条件を増やす前に、固定幅や長い文字が原因でないか確認します。横スクロールを隠すだけでは内容が読めなくなる場合があります。

ここは書き方の説明です。既存ファイルを全部消して貼り替えず、下の実習で対象を確認してから使います。

### 例を分解して読む：必要な項目から確認する

ここは、今日の実習に出てくる言葉を1つずつ読むための参照欄です。全部を追加する作業一覧ではありません。最初は使う項目だけを読み、つづり・記号・意味・画面の変化を対応させます。実習へ進むときはこの欄の後の手順へ戻ります。

#### 読み取り例：font-size（フォント・サイズとクランプ）

**何の言葉？** 最小値、望ましい値、最大値の範囲で文字サイズを調整します。7vwは画面幅の7%に相当する長さです。狭過ぎ・広過ぎのサイズを上下限で抑えます。

```css
.hero h1 {
  font-size: clamp(2rem, 7vw, 5rem);
}
```

**上から順に読むと：** 「.hero h1で選ぶ要素に、font-sizeという項目を、clamp(2rem, 7vw, 5rem)という値で指定する」です。どの要素を選ぶかと、その要素の何を変えるかを別々に読みます。セレクターとプロパティ名は同じ役目の言葉ではありません。

- `.hero h1`は**対象**です。自分のHTMLにある要素名・class・idと対応するかを先に調べます。見本の名前を写すだけでは、存在しない対象には表示の変化が出ません。
- 開く`{`から閉じる`}`までが、この対象へ書く**規則の本体**です。前後にある別の要素への規則を巻き込まないように、区切りを追います。
- `font-size`が**プロパティ**、`:`の後の`clamp(2rem, 7vw, 5rem)`が**値**です。項目名と値を逆に書きません。HTMLの属性のように`=`で結ぶ書き方でもありません。
- `;`はこの宣言の終わりです。1つの規則へ次の項目を書くときも、宣言の区切りを保ちます。日本語の本文と違って、記号の種類が読み取りに関わります。

**表示との対応：** 正しく当たる条件なら、画面幅に応じて文字が変わり、上下限で止まることを確認します。コードにこの行があるというだけでは、最終的にこの値が採用された証拠にはなりません。選んだ要素のStylesで、採用・上書きの状態も対応させます。

**比べると理解しやすいこと：** vwだけにした場合と比べ、極端に小さく大きくならないかを見る。変更は作業用コピーで1項目ずつ行い、見る場所と画面幅をそろえて比較します。変化がなければ、まず元の状態との違いを言葉にします。

**この例で間違いやすいところ：** 切れるときは文字サイズだけでなく見出しの幅、長い語、行間も見る。全角記号に変わっていないか、値に必要な単位やかっこが残っているかも確かめます。原因が分からない間に別の場所へ同じ宣言を大量に追加せず、実際の対象と採用元を追います。

**理解の確認：** 「この指定は誰に当たる？」「どの項目を変える？」「画面のどこを見れば分かる？」を、この例の対象・項目・結果の言葉で説明してみましょう。説明のための読解例なので、この規則をそのまま全ページへ追加する課題ではありません。実際に変える範囲は今日の依頼と実習を使います。

**そこで止まったとき：** 端末名だけでは再現しにくいので数値の幅を残します。スマホを持っていなくても、幅を変えた検証はその方法を正直に書きます。 原因を調べる間は、最後に確かめられた状態を残します。分からない箇所を全部消してやり直すより、今のファイル・今のSTEP・出ている表示を特定すると相談しやすくなります。

**記録の考え方：** このSTEPで実際に見た結果を、今日の制作メモまたはWORKLOGの該当項目へ短く残します。例の成功文を先に写して完了扱いにしません。結果が違った場合も、どこまで進めたかを残せば次に再開する手がかりになります。


「レスポンシブ対応しました」だけではなく、どの幅で何を直したかを書きます。
