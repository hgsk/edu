### 言葉と構文の読み方

**影響範囲**は変更が関係するページ・項目。**ステージング**は公開前の確認先。**承認**は「この対象を公開してよい」という明示的な判断です。

```html
<p class="price">650円（税込）</p>
```

- `price`は価格へ見た目を付けるclass名。`650`だけを全ファイルで置換すると、別商品の価格も変える危険があります。商品名と税込・税別を一緒に確認します。
- **JSON-LD**は検索サービスなどが読める構造化データ。教材ではHTML内の`<script type="application/ld+json">`にあります。HTML本文を直しても自動では更新されません。文字列の`" "`・項目間の`,`を壊さないようにします。
- **差分**は変更前と変更後の違い。依頼の5件を分けて記録すると、どの変更を確認してもらうか説明できます。

ここは書き方の説明です。既存ファイルを全部消して貼り替えず、下の実習で対象を確認してから使います。

### 選択追加課題：Pythonで店舗案内を生成する

#### 言葉・構文を先に読む

- **Python（パイソン）：** データを扱い、生成プログラムを動かす言語。`.py`はPythonのファイルです。
- **文字列：** `"駅前店"`のように引用符で囲む文字。引用符・かっこ・コロン・カンマは半角です。
- **辞書：** `{"name": "駅前店"}`のように項目名（キー）と値を組にする入れ物。`shop.name`は渡された辞書の`name`を読むJinja2の書き方です。
- **リスト：** `[辞書1, 辞書2]`のように順に並べる入れ物。`BRANCHES`に支店の辞書を並べます。
- **真偽値：** Pythonの`True`（はい）と`False`（いいえ）。`closed`は「休業か」です。引用符で囲んだ`"False"`は文字列なので使いません。
- **テンプレート：** 固定のHTMLと、あとでデータが入る印を持つひな型。ブラウザはJinja2の印を処理できません。
- **テンプレートエンジン：** データをひな型に当てはめ、最終的な文字列を作る道具。ここではJinja2を使います。
- **生成HTML：** エンジンが書き出した結果。ブラウザにはこのファイルを開きます。Pythonをブラウザ内で実行する仕組みではありません。

例は別の題材です。下の実習で店舗データの名前へ読み替えます。

```jinja
<h1>{{ event.title }}</h1>
{% for session in sessions %}
  <p>{{ session.name }}</p>
  {% if session.cancelled %}
    <p>中止</p>
  {% else %}
    <p>{{ session.start }}</p>
  {% endif %}
{% endfor %}
```

- **`{{ ... }}`：** 値を文字として埋め込む印。かっこは二重です。
- **`{% for session in sessions %}`〜`{% endfor %}`：** リストから1件ずつ取り出し、間のHTMLを繰り返します。`session`はその1件につけた名前です。
- **`{% if ... %}`〜`{% else %}`〜`{% endif %}`：** 条件が真なら前半、偽なら後半のHTMLを選びます。両方を同時に出しません。
- **HTMLエスケープ：** データ中の`<`を`&lt;`、`&`を`&amp;`などへ変換し、文字をHTMLのタグと誤解させないこと。ブラウザ上では元の文字として読めます。用意済みの`render.py`はHTML用に有効化しています。`|safe`を付けたり、エスケープを無効化したりしません。データをJavaScript・URL・CSSへ埋める課題ではありません。
- **`StrictUndefined`：** 項目名の打ち間違いを空欄にせずエラーにする設定です。

**3つの役割：** `data.py`（内容）＋`templates/index.html`（構造と表示ルール）→`render.py`で生成→`output/index.html`（表示結果）。生成HTMLだけを直接直しても、次の生成で上書きされます。

<a id="python-form-concepts"></a>

#### 用語・構文・処理の流れ

- **Flask（フラスク）：** ブラウザからの要求を受け、Pythonの処理とHTMLの返答を結ぶ小さなWeb用ライブラリ。Jinja2を使えます。
- **GET：** ページを読む要求。この課題ではフォームと保存済み一覧を表示し、保存はしません。URLに`?item=...`を足しても保存されません。
- **POST：** 本文に値を入れて送る要求。この課題では検査して保存します。POSTであるだけでは暗号化や認証にはなりません。
- **Form data：** 通常の`<form method="post">`で送る名前と値。この課題の送信形式は既定の`application/x-www-form-urlencoded`です。日本語・空白・`&`などは送信時に符号化され、Flaskが読み戻します。`multipart/form-data`は主にファイル送信などで使う別の形式で、今回は不要です。
- **JSONとの違い：** JSONは`{"item":"架空ラテ"}`のような構造をJSON形式で送るもの。`Content-Type: application/json`と`request.get_json()`を使う別経路です。今回の`request.form`へJSONは入りません。JSONやmultipartを送ると415で拒否します。
- **`name`：** HTMLの入力欄につける送信キー。`name="item"`の値はPythonで`request.form.get("item", "")`と読みます。`id="item"`はラベルと結ぶための目印で、送信キーの代わりにはなりません。
- **関数：** `def validate(item, note):`で処理に名前を付け、`return`で結果を返します。関数の中は半角空白4つでそろえます。
- **`.get("item", "")`：** キーがないときも空文字を返します。**`.strip()`**は前後の空白を除きます。**`len(item)`**は文字数です。
- **入力チェック：** 商品名は空白を除いて必須・40文字以内。メモは任意・120文字以内。ブラウザの`required`と`maxlength`に加えて、Python側でも検査します。ブラウザを通さない送信もあるためです。
- **SQLite（エスキューライト）：** Python標準の`sqlite3`で使えるファイル型データベース。別のDBサーバーを登録・起動する必要はありません。
- **SQL：** データベースに保存・読込を頼む言葉。`INSERT`は行を追加、`SELECT`は行を読む、`ORDER BY id DESC LIMIT 20`は新しいIDから最大20件です。21件目以降の古い記録は消えず、一覧の外に残ります。
- **パラメーター化：** SQLの形と値を分けること。値を`f"...{item}..."`や`+ item`でSQLへ連結しません。

別題材の書き方の例です。

```python
def validate_title(title):
    errors = []
    if not title:
        errors.append("題名は必須です")
    return errors

with db:
    db.execute("INSERT INTO ideas (title) VALUES (?)", (title,))
```

`errors`はエラー文を並べるリスト。空リストならエラーなしです。`with db:`は正常終了時に変更を確定（コミット）し、途中の例外では取り消します。`?`に値を渡す部分がパラメーターです。値が1個のタプルは`(title,)`と末尾カンマを付け、今回の2個は`(item, note)`とします。

**今回の1往復：** GET `/`→空のフォームと一覧→POST `/`→`request.form`→入力検査→不正なら400とエラー画面／正しければINSERTとコミット→303でGET `/`へ移動→SELECT→Jinja2で一覧。保存後をGETへ戻すので、通常の再読み込みだけで再POSTしません。二重クリックなどあらゆる重複を防ぐ仕組みではありません。

**保存先：** 作業コピーの`instance/notes.sqlite3`です。初回起動でフォルダーとテーブルを作ります。`CREATE TABLE IF NOT EXISTS`なので、再起動しても既存データは消しません。Pythonの変数だけに保存した場合と違い、ファイルが残るから読み直せます。ファイルを移動・削除したり別の作業コピーを起動したりすると、同じ一覧にはなりません。

<a id="php-cli-concepts"></a>

#### 用語と最小限の構文

- **PHP（ピーエイチピー）：** HTMLに処理を埋め込めるプログラミング言語。Webサーバー以外にCLIでも実行できます。
- **CLI：** ターミナルのコマンドで動かす方式。`php hello.php`は「PHPでこのファイルを実行する」。`.php`をブラウザへ直接開く操作とは違います。
- **コンテナ：** 用意された実行環境でプログラムを動かす仕組み。**イメージ**はその環境の元、**タグ**はバージョン等の名前、**digest**は特定のイメージ内容を識別する値です。
- **ホスト：** 自分のPC。**コンテナ内：** 実行環境側。同じフォルダーでもパス表記が違います。
- **バインドマウント：** ホストの指定フォルダーをコンテナから見える場所へ対応させること。今回の作業コピーだけを`/work`へ対応させます。PC全体、ホーム全体、Dockerソケットは渡しません。
- **標準出力：** 実行結果が通常ターミナルへ流れる経路。画面へ出すこととファイルへ保存することは別です。

```php
<?php
$title = '架空イベント';
echo $title;
echo "\n";
```

`<?php`はPHP処理の開始。`$title`は変数で、先頭に`$`を付けます。`=`は代入、`echo`は標準出力へ文字を出す命令、`;`は文の終わりです。`"\n"`は改行。PHPだけのファイルは末尾の`?>`を省き、意図しない空白を出さないようにします。

```php
<h1><?= e($event['title']) ?></h1>
<?php foreach ($sessions as $session): ?>
  <p><?= e($session['name']) ?></p>
  <?php if ($session['cancelled']): ?>
    <p>中止</p>
  <?php else: ?>
    <p><?= e($session['start']) ?></p>
  <?php endif; ?>
<?php endforeach; ?>
```

- **`<?= ... ?>`：** `<?php echo ...; ?>`の短い書き方。PHPと固定HTMLを混ぜるときに使います。
- **配列：** `['name' => '駅前店']`はキーと値の組。`$shop['name']`で読む。`[$branch1, $branch2]`のように並べることもできます。PHPは両方を配列で表せます。Pythonの辞書の`:`と違い、対応には`=>`を使います。
- **`foreach ($sessions as $session):`〜`endforeach;`：** 配列から1件ずつ取り出して、間のHTMLを繰り返す構文です。
- **`if (...) :`〜`else:`〜`endif;`：** 真なら前半、偽なら後半を出す。PHPの真偽値は`true`と`false`。文字列`'false'`にはしません。
- **`include`：** 別のPHPファイルをこの場所で実行する。`render.php`が固定した`templates/index.php`を読み込みます。`$shop`と`$branches`を用意してからincludeするため、テンプレート内で読めます。入力値からincludeのパスを組み立てません。
- **`require`と`return`：** `require`は必須ファイルを読み込み、欠落時は止まります。`data.php`の`return [...]`で返された配列を、生成側が受け取ります。
- **`__DIR__`と`.`：** `__DIR__`はそのPHPファイルのある場所、`.`は文字列の連結。`__DIR__ . '/data.php'`なので、コマンドの実行場所に依存せず同じデータを読めます。
- **`e(...)`：** 配布済みの関数です。中で`htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8')`を呼び、`<`・`>`・`&`・両方の引用符をHTML用にエスケープします。不正なUTF-8は置換します。PHPのecho自体は自動エスケープしないため、データをHTMLへ出す箇所は必ず`e`を通します。

`render.php`は出力バッファ（`ob_start`）へテンプレートの出力を集め、文字列として返します。`build.php`はそのUTF-8文字列をファイルへ保存します。今回はデータをHTMLの本文だけへ入れ、URL・JavaScript・CSSには埋め込みません。

#### STEP 1　WSL内の既存ランタイムと修正版を確認する

**WSL2はLinuxを動かす環境であり、コンテナランタイムそのものではありません。** この実習はWSL内に学校が準備済みのネイティブDocker Engine、またはrootless Podmanを使います。Docker DesktopやRancher DesktopのWindows連携CLIを前提にしません。WindowsへPHP本体を追加する必要もありません。

Windows PowerShellで教材ルートを開き、次を実行します。`Ubuntu`は`wsl --list --verbose`に実在する学校指定のディストリビューション名です。別名の場合は読み替えます。

```powershell
wsl --list --verbose
wsl -d Ubuntu --cd (Get-Location).Path
```

ここから先は**WSL内のBash**です。`pwd`で`/mnt/c/.../edu`等のLinuxパスになり、`ls README.md hht`で教材ルートを確認します。`C:\...`というWindowsパスをLinuxコンテナへ渡しません。

```bash
id
command -v docker
command -v podman
```

学校でネイティブDocker Engineが準備済みなら、以下を使います。

```bash
engine=(docker --host unix:///var/run/docker.sock)
readlink -f "$(command -v docker)"
"${engine[@]}" info
```

`engine`はコマンドと引数をまとめたBash配列です。`"${engine[@]}"`は、その引数の区切りを保って実行します。実体が`/mnt/c/Program Files/...`や`/mnt/wsl/docker-desktop/...`なら、選んだネイティブ環境ではありません。ローカルの`/var/run/docker.sock`が存在し、現在のユーザーのままで`info`が成功することが必要です。

学校で**rootless Podman**が準備済みなら、代わりに次を使います。通常ユーザーで実行し、以後の`engine`をこちらに揃えます。

```bash
engine=(podman --remote=false)
readlink -f "$(command -v podman)"
"${engine[@]}" info
```

**ランタイムがない、ソケットがない、権限エラーなら停止です。** 無断インストール、sudo実行、グループ追加、デーモンの公開、ファイアウォール・仮想化・セキュリティ設定変更はしません。WSLへ入れたことだけでコンテナ実行可と判断せず、表示を保存して講師へBLOCKEDを報告します。

実行環境の確認後、教材の開始データをWSLの本人用フォルダーへコピーします。以下は現在の教材ルートを`repoPath`へ記録する例です。同名の作業フォルダーが既にあれば、そこで止めて別名を選び、以後も読み替えます。

```bash
repoPath="$(pwd -P)"
mkdir -p "$HOME/hht"
test ! -e "$HOME/hht/php-template-work" && cp -R "$repoPath/hht/hands-on/php-cli-template/starter" "$HOME/hht/php-template-work"
```

コピーが成功した場合だけ進み、開始ソースを別の`before/`へ保存します。Linux側の`$HOME/hht/php-template-work`が今回の本人用作業場所です。既存フォルダーへ重ねません。UTF-8・BOMなしで編集します。

```bash
cd "$HOME/hht/php-template-work"
image='docker.io/library/php:8.4.27-cli-bookworm'
"${engine[@]}" pull "$image"
```

**採用予定は修正版8.4.27です。** [PHP公式の2026-10-21告知](https://www.php.net/archive/2026.php)で確認していますが、本体公開とコンテナの公開は別です。[公式イメージ](https://hub.docker.com/_/php)の修正版CLIを使い、`manifest unknown`／`no such manifest`なら公開待ちで停止します。旧版・RC・可変タグのキャッシュへ切り替えません。`docker.io/library/`まで指定することで、Podmanでも別レジストリの同名イメージを選びません。

pull成功後だけ、実際のCLIバージョンとdigestを確認します。

```bash
"${engine[@]}" run --rm --network none "$image" php --version
"${engine[@]}" image inspect "$image" --format '{{json .RepoDigests}}'
```

期待値は`PHP 8.4.27 (cli)`を含む表示と`sha256:...`です。実測値をWORKLOGへ記録します。タグも再ビルドでdigestが変わる場合があるので、厳密な再現記録にはdigestも残します。未取得の値を教材の実測値として書きません。

#### STEP 2　Linuxパスでマウントし、短いechoを実行する

`hello.php`のTODO 0を`echo "PHPでHTMLを作る\n";`へ変更して保存します。同じWSL Bashで次を実行します。

```bash
taskPath="$(pwd -P)"
userArgs=(--user "$(id -u):$(id -g)")
if [ "${engine[0]}" = podman ]; then userArgs+=(--userns=keep-id); fi
"${engine[@]}" run --rm --network none "${userArgs[@]}" --mount "type=bind,source=$taskPath,target=/work" --workdir /work "$image" php hello.php
```

期待値は`PHPでHTMLを作る`と改行です。

- **ホスト側**はWSL内の`$HOME/hht/php-template-work`、**コンテナ側**は`/work`。バインドマウントでこの作業コピーだけを対応させます。WSL全体、Windows全体、ホーム全体、Dockerソケットは渡しません。
- `--workdir /work`により`hello.php`は`/work/hello.php`です。Linuxパスを使い、空白がある場合もマウント指定全体の引用符を保ちます。フォルダー名にカンマは使いません。
- `--user`で生成物の所有者を本人のUID/GIDへ合わせます。rootless Podmanでは`--userns=keep-id`で本人のID対応を維持します。これはこのコンテナの指定で、OSのユーザー・権限設定を変更する操作ではありません。
- `--network none`は実行中のネットワークを使わない指定。pullはその前に必要です。`--rm`は終了したコンテナを除去し、マウントした作業ファイルは残します。
- Webサーバー、ポート公開、特権、ホストネットワークは使いません。権限エラーをsudoや権限緩和で回避せず停止します。

#### STEP 3　データとテンプレートを完成させる

まず`data.php`だけを編集します。店名は保持し、お知らせを`'<臨時案内> & 週末'`、駅前店の営業時間を`'09:00〜19:00'`へ変更します。公園店は`closed => true`と元の営業時間を保持します。最後に`name => '港店'`、`hours => '12:00〜17:00'`、`closed => false`の配列を追加します。キーも文字列なので引用符で囲み、項目間・店舗間のカンマを保持します。

次に`templates/index.php`のTODOを編集します。

1. **TODO 1：** h1に`$shop['name']`、お知らせ段落に`$shop['notice']`を、短縮echoと`e`を使って埋め込む。
2. **TODO 2：** `$branches`から`$branch`を取り出すforeachでli全体を囲む。h3に`$branch['name']`をエスケープして埋め込む。終了の`endforeach;`はliの後、ulの前。
3. **TODO 3：** `$branch['closed']`でifを分け、真なら`<p>本日休業</p>`、偽なら`<p>営業時間：…</p>`の`…`に`e($branch['hours'])`を出す。`endif;`で閉じる。

固定HTMLのmain、見出しの順番、ul/liは保持します。`render.php`の`e`を削除したり、データをそのままechoしたりしません。

#### STEP 4　ファイルへ生成しブラウザで確認する

```bash
"${engine[@]}" run --rm --network none "${userArgs[@]}" --mount "type=bind,source=$taskPath,target=/work" --workdir /work "$image" php build.php
```

期待値は`Generated: output/index.html (UTF-8)`です。コンテナ内の`/work/output/index.html`は、WSLの`$HOME/hht/php-template-work/output/index.html`に対応します。PHPが`file_put_contents`で直接書くので、保存データはWindows PowerShellのテキスト変換を通りません。

**`docker run ... > output/index.html`や`Out-File`でHTMLを保存しません。** Windows PowerShell等では標準出力をテキストとして変換し、UTF-16等になる場合があります。今回の保存経路は常にPHPの`build.php`です。標準出力を観察する場合だけ、同じコマンドの末尾を`php build.php --stdout`にします。これはHTMLをターミナルへ出すモードで、ファイル保存とは別です。

WSL Bashで`explorer.exe .`を実行し、開いた本人の作業フォルダーの`output/index.html`をWindowsブラウザで開きます。これはファイルを開くためのWSL相互運用で、コンテナランタイムやHTTPサーバーをWindows側で動かす操作ではありません。Webサーバーは起動しません。店舗名、`<臨時案内> & 週末`という文字、駅前店09:00〜19:00、公園店「本日休業」、港店12:00〜17:00が読めることを確認します。テンプレートの`.php`を直接開いても生成されません。

VS Codeで生成HTMLも開き、お知らせのソースが`&lt;臨時案内&gt; &amp; 週末`、文字コードがUTF-8であることを確認します。`<?php`や`<?=`が残っていれば生成HTMLを開いているかを確認します。`view-source:`は使いません。PHPの実行画面・生成結果の画像は実測再開後にここへ追加する必要があり、現在は未撮影です。

### 選択追加課題：URLのパスで画面を変え、エスケープを比較する

[用語と仕組み](#path-concepts) · [実習](#path-actions) · [完成条件・提出](#path-done)

**依頼者：** NORTH LIGHT COFFEEの佐藤さん。**見る人：** 来店前のお知らせを読む人。

> URLごとにお知らせの文面を変えたいです。ただし、URLに入った文字が勝手に見出しになったり、色を変えたりしないようにしてください。手元の比較画面で、その違いも説明してください。

**目的：** パスパラメータをルートで受け、固定テンプレートへ渡して表示する。同じ入力を文字として表示する場合とHTMLとして解釈する場合を比較し、表示改変を防ぐ理由を理解します。[フォーム課題](#python-form)を終えてから、別枠60〜90分を目安に進めます。所要時間は初学者未実測です。

**対象：** 本人の作業コピーの`app.py`のTODO A・Bと、`templates/notice.html`のTODO C。**対象外：** 継続サイト、他の追加課題、外部サイト、Cookie・認証情報、JavaScript、外部送信、永続保存。PHP CLIはファイルを生成する仕組みで、HTTPルーティングを自動提供しません。この課題は既存のFlaskで行います。

<a id="path-concepts"></a>

#### 用語・データの流れ

- **ルーティング：** 要求されたURLのパスを、処理するPython関数へ対応させること。
- **パスパラメータ：** `/notice/週末メニュー`の`週末メニュー`に当たる、パスの一部として受け取る値。Flaskでは`@app.get("/notice/<path:message>")`の印に一致した値が`def notice(message):`へ渡ります。`path:`は値の中のスラッシュも扱えるコンバーターです。
- **クエリパラメータ：** URLの`?`以降の名前と値。`/notice/週末メニュー?view=compact`では、本文の値はパス、`view=compact`はクエリです。`request.args.get("view", "full")`で別に読みます。フォームPOSTの`request.form`とも別です。
- **URLエンコード：** `<`・空白・日本語などをURLで運ぶための表現へ変えること。たとえば`<`は`%3C`、`>`は`%3E`、`/`は`%2F`。Flaskが復号した文字列を渡すので、この課題でさらに`unquote`を重ねません。
- **HTMLエスケープとの違い：** URLエンコードはURLで運ぶため、HTMLエスケープはHTMLの構文と文字を区別するためです。`%3C`を使って運んでも、復号後の`<`をHTMLへそのまま出せばタグになり得ます。
- **テンプレートへの受渡し：** `render_template("notice.html", message=message, view=view)`は、固定したテンプレートへ名前付きで値を渡します。受け取ったパスをテンプレート名、ファイル名、includeのパスに連結しません。
- **自動エスケープ：** 通常のJinja2 HTMLテンプレートの`{{ message }}`はデータを文字として出します。`|safe`や`Markup`で解除すると、文字がHTMLとして解釈される可能性があります。
- **HTML注入とXSS：** 文字列がHTMLとして解釈され、見出し等が増えるのが今回のHTML注入です。XSSはスクリプト等の実行に関わる問題であり、見出しが増えたことだけでXSS実行を証明したとは言いません。今回JavaScriptは使いません。

例：`GET /notice/週末メニュー?view=compact` → Flaskのルート → Pythonの`message`と`request.args` → 固定テンプレート → HTML返答 → ブラウザ。URLによって返答が変わっても、サーバーのソースファイルが書き換わったわけではありません。

<a id="path-actions"></a>

#### STEP 1　安全な通常アプリを用意する

`hht/hands-on/python-path-escaping/starter`をルート直下へ`python-path-work`としてコピーし、開始ソースの別コピーを`before/`へ保存します。既存作業を上書きしません。教材ルートで新しいPowerShellターミナルを開き、次を実行します。

```powershell
cd python-path-work
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

前の課題と同じPython 3.11以上とFlaskです。macOS/Linuxでは仮想環境を`python3`で作り、以後を`./.venv/bin/python`へ読み替えます。導入済み環境を使い、取得や起動が許可されない場合は設定変更せず停止して講師へ報告します。

`http://127.0.0.1:5002/`をブラウザで開きます。入口には「週末メニュー」「営業時間の案内（compact）」の2リンクがあります。開始時はリンク先の本文が未実装です。

![実際の通常アプリ入口。2種類のお知らせへのリンクが並ぶ](../../assets/python-path-escaping/index.png)

#### STEP 2　パスを表示し、クエリを別に扱う

1. **TODO A：** `displayed_message(message)`の返り値を、受け取った`message`にする。HTML文字列を組み立てたり、`Markup`を付けたりしない。
2. **TODO B：** `selected_view(arguments)`で`arguments.get("view", "full")`を`view`に代入する。`view`が`{"full", "compact"}`に含まれなければ`abort(400)`、含まれればその値を返す。受信値をファイルパスへ使わない。
3. **TODO C：** `templates/notice.html`の`id="message"`内の仮文を、通常の変数埋め込み`{{ message }}`へ置き換える。`|safe`は付けない。テンプレート名とほかの部分は保持する。

保存→通常アプリのターミナルでCtrl+C→同じ起動コマンド→ブラウザ再読込の順で反映します。入口の「週末メニュー」を押すと本文と`表示モード：full`、2つ目では別本文と`表示モード：compact`が見えます。compactでは補足文が省かれます。

アドレスの本文だけを別の架空の短文へ変えて、再表示を確認します。`?view=unknown`へ変えた場合は400、`/notice?message=週末メニュー`はパス部分がないので404です。意図した拒否とサーバー故障を区別します。

#### STEP 3　同じ無害なHTML入力を通常版へ渡す

比較に使う入力は、次の1つだけです。

```html
<h2 class="demo-red">臨時休業（架空）</h2>
```

サーバーが動くターミナルとは別のPowerShellを開き、次を実行します。出たURLをコピーしてブラウザへ貼ります。

```powershell
$demoInput = '<h2 class="demo-red">臨時休業（架空）</h2>'
$encoded = [uri]::EscapeDataString($demoInput)
"http://127.0.0.1:5002/notice/$encoded"
```

macOS/Linuxではブラウザのアドレスへ元の文字列を貼る方法ではなく、Pythonの`urllib.parse.quote(入力, safe="")`等で値の部分だけをURLエンコードします。URL全体をエンコードすると`http://`やルートの区切りまで変わります。

**通常版の期待結果：** `<h2 class="demo-red">...`というタグ自体が文字として読めます。新しい見出しや赤い本文にはなりません。

![通常ページでは同じ入力がタグの文字列として表示され、見出しにならない実画面](../../assets/python-path-escaping/safe.png)

#### STEP 4　隔離した教育専用アプリで表示改変を比較する

通常アプリはそのままにし、別ターミナルを`python-path-work`で開いて次を実行します。

**期待結果：** 上の安全版はタグの文字列のまま。下の危険版の教育用再現では、`臨時休業（架空）`が大きな赤い見出しになります。テンプレートに元からある`demo-red`用のCSSが、挿入されたh2へ適用されます。単なるお知らせ入力がページの構造・見た目を変えることを確認します。

![同じ入力を比較した実画面。安全版はタグ文字列、教育用危険版は赤い見出しとして表示される](../../assets/python-path-escaping/comparison.png)

比較アプリは**この無害な入力と完全一致する場合だけ**受理し、そのほかは400です。任意の入力へ`Markup`を付ける実装ではありません。CSPでスクリプト・外部リソース・フォーム送信も禁止しています。この再現は任意HTML・JavaScript・外部送信を試す入口ではありません。比較用ファイル・設定・エスケープ解除を通常アプリや提出正解へコピーしません。

**何が書き換わった？** 生成された返答HTMLの解釈が変わり、ブラウザの画面が改変されました。サーバーの`app.py`・テンプレート・DBを書き換えたわけではなく、永続化する例でもありません。実在サイトの内容変更や攻撃は行いません。

#### STEP 5　考察して安全な修正を説明する

次の架空の不適切なコードを、WORKLOGに安全な形へ直して書きます。通常アプリへ危険な行を入れて実行する作業ではありません。

```jinja
<div>{{ message | safe }}</div>
```

解除を取り除いた`{{ message }}`を使い、同じ入力がタグの文字になる理由を説明してください。長さチェックが通ってもエスケープが必要な理由、URLエンコードだけではHTML注入を防げない理由も書きます。

考察すること：

- ルートのパス値と`view`のクエリ値は、どこでどう読まれたか。
- 安全・危険の表示で入力は同じか。生成された要素と見た目はどう違うか。
- 今回の表示改変だけで、JavaScript実行やサーバーファイルの書換えまで証明できるか。
- HTML本文以外の属性・URL・JavaScript・CSSへ入れる場合も、同じ処理だけでよいか。

最後の問いでは、**表示する場所に合う対策が必要**と整理します。HTML属性は引用符を保つ、URLは許可する方式・宛先を検証する、JavaScript/CSSへ入力を直接埋め込まない等、本文の自動エスケープだけで全用途を安全にできるとは考えません。今回の実装はHTML本文だけです。
