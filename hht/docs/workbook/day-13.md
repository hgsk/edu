### 言葉と構文の読み方

**animation（アニメーション）**は時間に沿った見た目の変化。**keyframes（キーフレーム）**は途中と終わりの状態を定義する書き方です。

```css
@keyframes notice-in {
  from { opacity: 0; }
  to { opacity: 1; }
}
.notice {
  animation: notice-in 0.4s ease;
}
@media (prefers-reduced-motion: reduce) {
  .notice { animation: none; }
}
```

- **`notice-in`**は自分で付ける動きの名前。`animation`で同じ名前を指定して使います。
- **`from`／`to`**は開始／終了、**`opacity`**は不透明度。0は透明、1は不透明です。
- **`prefers-reduced-motion: reduce`**は端末で動きを減らしたい設定のとき。`none`はその動きを使わない値です。
- **production**は本番相当の配置先、**ロールバック**は公開前へ戻すこと。CIのPASSや提出の受領は公開承認ではありません。

ここは書き方の説明です。既存ファイルを全部消して貼り替えず、下の実習で対象を確認してから使います。

### 例を分解して読む：必要な項目から確認する

ここは、今日の実習に出てくる言葉を1つずつ読むための参照欄です。全部を追加する作業一覧ではありません。最初は使う項目だけを読み、つづり・記号・意味・画面の変化を対応させます。実習へ進むときはこの欄の後の手順へ戻ります。

#### 読み取り例：animation（アニメーション）

**何の言葉？** notice-inという名前のkeyframesを0.4秒で再生します。この例は繰り返しを指定していないので通常は1回です。再読み込み時も再生される場合があります。

```css
.notice {
  animation: notice-in 0.4s ease;
}
```

**上から順に読むと：** 「.noticeで選ぶ要素に、animationという項目を、notice-in 0.4s easeという値で指定する」です。どの要素を選ぶかと、その要素の何を変えるかを別々に読みます。セレクターとプロパティ名は同じ役目の言葉ではありません。

- `.notice`は**対象**です。自分のHTMLにある要素名・class・idと対応するかを先に調べます。見本の名前を写すだけでは、存在しない対象には表示の変化が出ません。
- 開く`{`から閉じる`}`までが、この対象へ書く**規則の本体**です。前後にある別の要素への規則を巻き込まないように、区切りを追います。
- `animation`が**プロパティ**、`:`の後の`notice-in 0.4s ease`が**値**です。項目名と値を逆に書きません。HTMLの属性のように`=`で結ぶ書き方でもありません。
- `;`はこの宣言の終わりです。1つの規則へ次の項目を書くときも、宣言の区切りを保ちます。日本語の本文と違って、記号の種類が読み取りに関わります。

**表示との対応：** 正しく当たる条件なら、読み込んだ際にお知らせが変化することを確認します。コードにこの行があるというだけでは、最終的にこの値が採用された証拠にはなりません。選んだ要素のStylesで、採用・上書きの状態も対応させます。

**比べると理解しやすいこと：** hover時の変化を補間するtransitionと、名前付きの時間変化を定義するanimationを区別する。変更は作業用コピーで1項目ずつ行い、見る場所と画面幅をそろえて比較します。変化がなければ、まず元の状態との違いを言葉にします。

**この例で間違いやすいところ：** 名前がkeyframesと一致するか、動き低減の条件で止まっていないかを確認する。全角記号に変わっていないか、値に必要な単位やかっこが残っているかも確かめます。原因が分からない間に別の場所へ同じ宣言を大量に追加せず、実際の対象と採用元を追います。

**理解の確認：** 「この指定は誰に当たる？」「どの項目を変える？」「画面のどこを見れば分かる？」を、この例の対象・項目・結果の言葉で説明してみましょう。説明のための読解例なので、この規則をそのまま全ページへ追加する課題ではありません。実際に変える範囲は今日の依頼と実習を使います。

### 実習の進め方

### STEP 1　お知らせの案を2つ作る

**このSTEPで行うこと：2案の比較**

同じお知らせ内容で、動く案と静かな案を作業用コピーで比較します。目立ち方だけでなく、読むのを妨げないか、動きを減らす設定でどうなるかを記録します。

**できたかの見分け方：** 同じ内容の2案を根拠とともに比較できることを、編集画面だけでなく必要な表示・操作で確かめます。「操作した」ことと「期待した結果を見た」ことを分けて考えます。

**そこで止まったとき：** 静かな案だけ文章を短く変えると動きの比較になりません。比較する内容の条件をそろえて、それぞれの良い点と気になる点を書きます。 原因を調べる間は、最後に確かめられた状態を残します。分からない箇所を全部消してやり直すより、今のファイル・今のSTEP・出ている表示を特定すると相談しやすくなります。

**記録の考え方：** このSTEPで実際に見た結果を、今日の制作メモまたはWORKLOGの該当項目へ短く残します。例の成功文を先に写して完了扱いにしません。結果が違った場合も、どこまで進めたかを残せば次に再開する手がかりになります。


例:

- 少し動く案
- 動かない静かな案

それぞれの良い点・気になる点を書きます。

公開日時・URL・対象・確認結果・未対応を報告します。復元が必要だった場合は、戻した時刻・対象・現在の状態も書きます。

**できたかの見分け方：** 公開先の現状と残る課題が読み手に伝わることを、編集画面だけでなく必要な表示・操作で確かめます。「操作した」ことと「期待した結果を見た」ことを分けて考えます。

**そこで止まったとき：** 一部未確認なのに全項目完了とまとめません。利用者や依頼者が現状を判断できるよう、確認済みと未確認を分けます。 原因を調べる間は、最後に確かめられた状態を残します。分からない箇所を全部消してやり直すより、今のファイル・今のSTEP・出ている表示を特定すると相談しやすくなります。

**記録の考え方：** このSTEPで実際に見た結果を、今日の制作メモまたはWORKLOGの該当項目へ短く残します。例の成功文を先に写して完了扱いにしません。結果が違った場合も、どこまで進めたかを残せば次に再開する手がかりになります。


次を含めます。

- 公開URL
- 変更内容
- 確認した内容
- 未対応事項

### 完了チェック

- [ ] 2つの案を比較した
- [ ] 選ばれた案を確認した
- [ ] 公開の承認を確認した
- [ ] 公開前の状態へ戻せる
- [ ] 公開後にURLを確認した
- [ ] スマートフォンでも確認した
- [ ] 完了報告を書いた

### 完成条件・提出するもの

**入力:** お知らせの表現依頼、最終承認

**完成物:** 動く案・静かな案、承認記録、バックアップ、公開、完了報告

**完成条件:**

- `prefers-reduced-motion`で不要な動きを止める
- 公開前に承認と対象ファイルを照合する
- [採用案の明示承認メール](../../student/requests/day13-release-approval.md)または講師指定の同等文面を受け取るまで公開しない
- 公開前バージョンへ戻せる
- 公開URLでページ、リンク、画像、スマホを確認する
- 完了報告に未対応事項も書く

**証拠:** 承認記録、バージョンID、公開URL、公開後チェック

**追加チャレンジ:** 公開後に不具合が見つかった想定で、復元を練習しよう。
