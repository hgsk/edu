### 言葉と構文の読み方

**可読性**は文字の読みやすさ。**コントラスト**は文字と背景の明暗の差。**アクセシビリティ**は、使い方や状況が違っても情報や操作へ到達できるようにすることです。

```css
body {
  color: #20201d;
  background-color: #fffdf7;
  font-size: 1rem;
  line-height: 1.7;
}
```

- **`font-size`**は文字サイズ、**`line-height: 1.7;`**は文字サイズに対する行の高さの倍率。倍率なのでここには単位を付けません。
- **`font-family`**は使うフォントの候補。複数の候補は`,`で区切り、使えるものから選ばれます。
- **200%拡大**はブラウザのズーム。画面幅の変更とは別に、文字や部品を大きくして使えるか確認します。
- **公開後確認**は公開先の実URLで見ること。PC内の編集画面だけを見て終了しません。戻せる版と対象ファイルも記録します。

ここは書き方の説明です。既存ファイルを全部消して貼り替えず、下の実習で対象を確認してから使います。

### 例を分解して読む：必要な項目から確認する

ここは、今日の実習に出てくる言葉を1つずつ読むための参照欄です。全部を追加する作業一覧ではありません。最初は使う項目だけを読み、つづり・記号・意味・画面の変化を対応させます。実習へ進むときはこの欄の後の手順へ戻ります。

#### 読み取り例：font-family（フォント・ファミリー）

**何の言葉？** 使う書体の候補を順に書きます。system-uiは端末のUIの書体、sans-serifは候補が使えない場合などの総称です。端末によって実際の書体は変わります。

```css
body {
  font-family: system-ui, sans-serif;
}
```

**上から順に読むと：** 「bodyで選ぶ要素に、font-familyという項目を、system-ui, sans-serifという値で指定する」です。どの要素を選ぶかと、その要素の何を変えるかを別々に読みます。セレクターとプロパティ名は同じ役目の言葉ではありません。

- `body`は**対象**です。自分のHTMLにある要素名・class・idと対応するかを先に調べます。見本の名前を写すだけでは、存在しない対象には表示の変化が出ません。
- 開く`{`から閉じる`}`までが、この対象へ書く**規則の本体**です。前後にある別の要素への規則を巻き込まないように、区切りを追います。
- `font-family`が**プロパティ**、`:`の後の`system-ui, sans-serif`が**値**です。項目名と値を逆に書きません。HTMLの属性のように`=`で結ぶ書き方でもありません。
- `;`はこの宣言の終わりです。1つの規則へ次の項目を書くときも、宣言の区切りを保ちます。日本語の本文と違って、記号の種類が読み取りに関わります。

**表示との対応：** 正しく当たる条件なら、その端末で使える候補の書体になることを確認します。コードにこの行があるというだけでは、最終的にこの値が採用された証拠にはなりません。選んだ要素のStylesで、採用・上書きの状態も対応させます。

**比べると理解しやすいこと：** 特定のPCの見た目だけを前提に、文字幅をぎりぎりに固定しないよう比較する。変更は作業用コピーで1項目ずつ行い、見る場所と画面幅をそろえて比較します。変化がなければ、まず元の状態との違いを言葉にします。

**この例で間違いやすいところ：** 別PCで折り返しが変わっても読めるか、固定幅・高さへ依存していないかを見る。全角記号に変わっていないか、値に必要な単位やかっこが残っているかも確かめます。原因が分からない間に別の場所へ同じ宣言を大量に追加せず、実際の対象と採用元を追います。

**理解の確認：** 「この指定は誰に当たる？」「どの項目を変える？」「画面のどこを見れば分かる？」を、この例の対象・項目・結果の言葉で説明してみましょう。説明のための読解例なので、この規則をそのまま全ページへ追加する課題ではありません。実際に変える範囲は今日の依頼と実習を使います。
