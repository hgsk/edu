# 教材を変更したときの整合性検査

課題・完成条件の正本は[学生ワークブック](../docs/student-workbook.md)です。この検査は受講者の完成物の採点ではなく、指示どおりに着手できる配布前データの検査です。

リポジトリのルートで実行します。VS Codeの「タスクの実行」から「教材と配布サイトの整合性を確認」も使えます。

```sh
python hht/scripts/validate-course.py
python -m unittest discover -s hht/scripts -p "test_course_site.py"
```

失敗時は対象ファイルと食い違いが`FAIL`で表示され、終了コード1になります。GitHubのQualityでも両方を実行します。

**自動で照合するもの**

- 開始用サイトとDAY 3・4の計9ページ：ナビの項目・順序・移動先・現在ページ、対象ボタンと商品一覧の参照先。
- 開始時の商品名・価格・件数、創業の文章、営業時間の表示とJSON-LD、店舗情報、仮文章、フッターの年。
- HTMLのローカルリンク・画像・CSS、CSS画像、ページ内リンクの実在とidの重複。
- DAY 3・4の開始フォルダーと配布ZIPの全ファイル名・全バイト。片方だけ更新すると失敗。
- ワークブックの前提を示す文と配布ZIPの検査対象への登録漏れ。

**変更するときの扱い**

1. ワークブックの対象DAYと依頼資料を先に確認します。
2. 配布する開始データを直します。DAY 3のCSS競合やDAY 4の改善前の構造は演習の入力なので、通常サイトに合わせて消さないでください。
3. 開始データを変更した場合は、同じ内容で配布ZIPも作り直します。
4. 前提自体を変更した場合だけ、[機械検査用の入力データ](../scripts/course-site-contract.json)と[回帰テスト](../scripts/test_course_site.py)を見直します。エラーを消すために検査条件だけ緩めないでください。
5. 上のコマンドを実行し、ブラウザでも該当ページを開きます。必要な操作を試し、説明の近くのスクリーンショットも更新します。


## 番号付き画像を更新する

画像の対象は[撮影位置の定義](../scripts/workbook-targets.json)で管理します。1枚につき最大3か所とし、画面の対象要素をセレクターで指定します。画像の番号に対応する「見る場所」を、ワークブックの画像直下に置きます。

Playwrightを利用できるNode.js環境で、リポジトリのルートから実行します。

```sh
node hht/scripts/capture-workbook.cjs
python hht/scripts/validate-course.py
```

撮影処理はローカルの実ページを開き、本文を変更せず番号と囲みだけを重ねます。対象が見つからない・複数ある場合は停止し、撮影用ブラウザを終了します。ポートフォリオのコード参照図は、原本コードから生成する図として実画面と区別します。

HTML・CSS・写真や撮影定義の変更後に画像を更新し忘れると、通常の教材検査がハッシュの不一致で失敗します。番号の説明が画像の近くにない場合も失敗します。画像の更新後は、番号が対象の文字や価格を隠していないかを目視確認します。
