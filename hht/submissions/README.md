# 全15回のPR提出と講師レビュー

課題と完成条件の正本は[日別ワークブック](../docs/student-workbook.md)です。  
教材更新・保存・提出先確認は[共通手順](../docs/workbook/common.md#submission-policy)に従います。  
提出用ZIPは作りません。

## 提出物を残す

DAY1〜9は制作ファイルと必要なCSS・画像を教材の外へ保護します。  
DAY10〜15は教材の外の同じportfolioを続け、作品のGit履歴を残します。  
教材のPull・破棄で提出物や作品を失わない場所へ保存します。

提出先が案内されたら、本人用リポジトリの指定作業ブランチに制作ファイルと次の記録を入れます。  
以下は提出先内の配置例で、教材edu内への保存指示ではありません。  
既存の`hht/submissions/day-XX`形式の記録は削除せず、講師がCIの`records-root`を合わせます。

```text
submissions/day10/
  WORKLOG.md
  screenshots/
  evidence/
```

**WORKLOG：** PR #20の8項目を引き継ぎます。  
短い作業メモから転記でき、文章量・コミット数では評価しません。  
「なし」の場合も、確認した理由や範囲を記録します。

```markdown
# DAY10 WORKLOG
- 依頼: 見る相手と伝えたい内容
- 質問: 確認した質問と回答、または不要と判断した理由
- 変更した場所: 実際のファイルと変更内容
- 変更しなかった場所: 対象外とその理由
- 確認したこと: 表示幅・リンク・操作・結果、証拠ファイルの場所
- 未確認: 残件と次の対応、または確認できた範囲
- バージョン: 実際に表示確認した作品のコミットSHA
- 確認URL: 実際に開いたローカルURLまたは公開URL、対象パス、確認時刻
```

WORKLOG自身を含むコミットのSHAを同じコミットに書こうとする必要はありません。  
作品をコミットして確認し、そのSHAと証拠を後続コミットへ残せます。  
`screenshots/`には実際の確認画面、`evidence/`には確認結果や返信案などを残します。  
そのDAYで必要な証拠は日別本文を参照します。  
個人情報・認証情報・講師用回答を含めません。

## PRを渡し、修正する

講師指定の提出先・base・作業ブランチを確認してからPushします。  
教材`hgsk/edu`へ学生作品のPRを送るとは決めていません。  
1回の提出PRでは、対象DAYの作業と証拠を示します。  
DAY10以降は同じ作品を続けるため、次回の開始ブランチは前回の返却・マージ状況を講師と確認します。

PR本文にはDAY、目的、変更箇所、実際の確認結果、残件、確認したコミットSHAを書きます。  
Files changedで制作ファイル・WORKLOG・証拠と、対象外の混入を確認します。  
PR URLを講師指定の窓口へ渡します。  
講師の修正依頼は同じPRへ追加コミットし、WORKLOGへ再確認結果を追記して返します。  
マージ権限・返却方式は講師の案内に従います。

## CIの確認と講師レビュー

教材のQuality・Checkout Bytesは教材検証です。  
Student Assignmentは提出確認コードの回帰テストをWindows/Linuxで実行します。  
学生本人用リポジトリでは、講師が設定した再利用ワークフローで次を確認できます。

- 対象DAY、制作ファイル、WORKLOG8項目と確認したコミットSHA。
- ローカル表示または公開表示の確認URL。
- スクリーンショットと証拠ファイルの存在。
- 提出パスがリポジトリ外やシンボリックリンクを参照していないこと。

CIは学生のHTML・JavaScript・Pythonを実行しません。  
画像の内容、記録の真偽、リンクの実操作、権利・個人情報の確認、完成条件は講師がレビューします。  
FAILは再確認箇所で、成績の不合格ではありません。  
PASSも課題完成や公開承認ではありません。  
CI未設定・実行失敗は未検証と記録し、成功と読み替えません。

学生用CIの有効化は[講師向け統合記録と設定案](../instructor/pr-integration-20261031.md)を参照します。  
外部公開・相互レビュー・発表は後半の必須条件に追加しません。  
新しい採点基準は[評価ルーブリック](../docs/rubric.md)の確認事項として保留します。
