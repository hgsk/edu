# 数学講座の設計

## 依頼と目的

- **依頼者：** eduの教材作成者。
- **受講者：** ゲーム制作・プログラミングに必要な数学を学び直す人。中学数学から始める。
- **解決したいこと：** 式を計算できても、動きや条件を式にする場面で何を使えばよいか判断できない。
- **作るもの：** 基礎数学の説明・計算例・演習と、工学的な比較・検証を行う応用課題。
- **目指す到達点：** 目的に合う数学的表現を選び、数値例で確かめ、結果と制約を説明できる。

企画の根拠は、依頼された中学〜高校の領域一覧と、複素数・クォータニオン・ジンバルロックなどの応用課題の追加である。[既存の講座設計](../../hht/docs/course-design.md)にある「目的の確認から必要な技術へ進む」方針を引き継ぐ。

## 範囲と構成

基礎18単元と工学への応用10課題を設ける。中学・高校の内容を中心とし、行列・外積・数値計算・制御などは発展として補う。学校の履修順や学習指導要領の網羅を保証する構成ではない。

学習内容、前提、演習、完成条件、提出物は[学生ワークブックの数学編](../../hht/docs/workbook/math.md#math-course)に集約する。入口や講師資料には複製しない。

授業回数と時間、ゲームエンジンの指定は未確定。教材アプリはHTML・CSS・JavaScriptで実装し、外部依存なしでローカルから開ける。紙上計算と、各単元の代表的な現象を動かす数値モデルを組み合わせる。高度な証明、大学数学の網羅、実機ロボットの操作は今回の範囲外とする。

## 学び方

各単元は「依頼と完成条件を読む → 数学の意味をつかむ → 例題を確かめる → 別の入力で試す → 結果と限界を説明する」の順で進める。計算の速さだけで評価しない。

初学者の入口はB01（正負の数・分数・平方根）→B02（割合）→B03（方程式）→B05（座標）→B06（比例・反比例・一次関数）→B07（図形）→B11（樹形図）→B12（確率）→B13（データ）とする。学習段階を各単元へ表示し、高校・工学の用語には先に定義を添える。中学の領域の確認には[文部科学省「中学校学習指導要領（平成29年告示）解説 数学編」](https://www.mext.go.jp/component/a_menu/education/micro_detail/__icsFiles/afieldfile/2019/03/18/1387018_004.pdf)を参照した。証明・作図・空間図形の全内容を網羅する構成ではない。

全28単元に、前提へのリンク、2語以上の用語解説、2例以上の比較操作、ワークブック由来の読み取り確認を用意する。図の選択ごとに操作対象を明示し、本文で扱う全内容を一つの図で説明したとみなさない。読み取り確認は固定した問題文の数値を使い、図の現在の入力と混同しない。答えの正誤だけでなく計算の理由を返す。

品質確認では全単元・全図のアニメーションと全入力の観察可能な変化を調べる。本文の代表的な例題（3回被弾、回復時間、連立・二次方程式、期待値、戻す／戻さない確率）を画面操作で再現する。28単元の読み取り確認は正答・誤答の両方を試す。全単元の320・390・768・1440px表示と全図の390px表示を確認し、数値テストだけで完了としない。

基礎は番号順に進める。既習者は例題を説明し、演習を解ける単元を省略できる。応用には前提単元を明記し、特に3D回転では座標系・回転順序・クォータニオン成分順を固定する。

数学上の厳密な等号と、浮動小数点による近似を区別する。確率の理論値と有限回の観測結果、姿勢の表現と物理的な機構の制約も区別する。

## 計算を学ぶ方針

計算の速さと、条件を理解して計算できることを分ける。短い具体例は手でも確かめ、規則の発見や検算に使う。大量の値や複雑な計算は計算機へ任せられるが、出力を根拠なく正解としない。速度競争や意味のない大量反復、手計算の全面廃止を方針としない。

式変形では、式の値・定義域・解集合のどれを保っているかを確認する。非零で割る条件、二乗後の余分な候補、約分後の定義域などを段階に合わせて扱う。具体例から予想を作り、一般の式や図での証明、または反例探索へ進む。有限個の例の一致を一般命題の証明と扱わない。

計算機の結果は概算・符号・単位・上限下限・誤差で検証する。近似では省略項と誤差の見積もりを取り上げ、実際の誤差・誤差の上界・要求される許容値を区別する。共通方針、具体的な問い、解答と評価基準の正本は[ワークブックの数学編](../../hht/docs/workbook/math.md#math-course)に置く。

HTML教材ではワークブックから計算判断の演習を生成し、選択・理由の記述・解説・自己点検を一つの流れにする。選択肢の照合と記述の評価を分け、記述を機械的に採点したとは表示しない。B18の近似の誤差、A06の時間刻みと要求精度、A10の絶対誤差は、入力を変えて比較できるようにする。

## 実装教材を追加するとき

数学編の条件を参照し、操作対象の実アプリを用意する。開始・操作中・結果の実画面を撮影し、`hht/assets/math/` 以下へ保存する。画像は説明の近くに代替テキスト付きで配置する。撮影や実機確認が済むまで操作ハンズオンの完成とは扱わない。

アプリの操作手順は[実画面付き操作ガイド](../guide.html)に置く。説明の本文はワークブックから `scripts/build_lessons.py` で `lessons.js` へ生成し、課題条件を二重管理しない。各モデルは代表例を視覚化するもので、全課題の自動解答・自動採点は行わない。

再生は初期状態で停止し、手動の段階送りと再生位置変更を用意する。非表示のタブでは再生を停止する。入力と同じ単位の数値結果を図の外にも示し、キーボードで入力を変更できるようにする。端末の「動きを減らす」設定が有効になった場合も再生を停止する。
