# 第1章 仮説とその限界


[目次](../README.md) · [次の章：第2章 計測の作法](./lesson02.md)


**この章で学ぶこと：** 「メモリは高価なボトルネックだ」という仮説を、遅延、帯域、容量、価格、エネルギーの5次元へ分解し、成り立つ部分と反例を区別できるようになります。


最適化の議論は、「メモリが遅い」「計算が重い」という曖昧な言葉で始まりがちです。  
この章では仮説を5つの測れる量へ分解し、どの次元なら支持できて、どの次元では崩れるのかを確認します。  
以降の全章は、この分解を共通言語として使います。


## 考え方


- **遅延、帯域、容量は別の律速：**
  遅延は1回のアクセスの待ち時間、帯域は単位時間に運べる量、容量は載るかどうかです。  
  帯域を増やしても遅延はほぼ下がらず、容量を増やしても帯域は増えません。  
  「メモリがボトルネック」と言うときは、まずこの3つのどれなのかを特定します。


- **価格の2つの顔：**
  DRAMのビット単価は1980年から2020年にかけて約100万倍下がりました。  
  絶対価格では、メモリは計算機の歴史で最も安くなった部品のひとつです。  
  一方でSRAMやHBMのような速いメモリの相対価格と、システム費用に占めるメモリの割合は高く保たれています。


- **エネルギーは最も頑健な根拠：**
  DRAMアクセス1回にかかるエネルギーは、浮動小数点加算の数百倍から数千倍という見積もりがあります。  
  演算そのものより、データを運ぶことの方が電力予算を支配します。  
  だから最適化は、演算回数より先に移動バイト数を数えるのが有効です。


- **反例も仮説の一部：**
  大規模な行列積やLLMのプリフィル、キャッシュに収まる処理は計算律速です。  
  電力、熱、ネットワーク、パッケージングが律速になる局面もあります。  
  仮説は教条ではなく、最初に疑う先を決めるための道具として使います。


## ハンズオン：身近なシステムの律速を5次元で仮説立てる


1. 普段使うプログラムやサービスを1つ選び、遅いと感じる場面を1つ挙げます。
2. その場面について、遅延、帯域、容量、価格、エネルギーのどれが効いていそうか、根拠と一緒に書き出します。
3. 次に、メモリ以外の律速（計算、ネットワーク、同期など）の可能性も最低1つ挙げます。
4. 2つの仮説を区別するには何を測ればよいか、測定方法を設計します。


どちらの仮説が正しいかは、この時点では決めなくて構いません。  
測れる形に分解できたことが成果です。


## 代償と判断


この視点を濫用すると、すべての遅さをメモリのせいにして見当違いの最適化をします。  
仮説は検証の出発点であり、結論ではありません。  
実測が仮説と食い違ったら、仮説の方を更新します。


## 確認


- [ ] メモリの律速を遅延、帯域、容量に分解して説明できる

- [ ] 価格について、絶対価格と相対価格・費用割合を区別して説明できる

- [ ] 「常にメモリが律速」への反例を2つ挙げられる


**演習：** 自分の関わるシステムについて、律速の仮説を5次元で書いてください。  
あわせて、その仮説が外れている可能性と、それを見分ける測定を1つ書いてください。
