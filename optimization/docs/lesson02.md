# 第2章 計測の作法


[目次](../README.md) · [前の章：第1章 仮説とその限界](./lesson01.md) · [次の章：第3章 プログラミングモデルはメモリの嘘と約束](./lesson03.md)


**この章で学ぶこと：** Rooflineモデル、演算強度、Littleの法則、価値密度を使い、最適化の前に律速を特定し、手法の採否を数値で判断できるようになります。


最適化の失敗の多くは、手法の選択ミスではなく、測る前の思い込みです。  
この章では、以降の全章で使う4つの道具をそろえます。  
どの道具も、暗記ではなく自分のマシンで確かめることを前提にします。


## 考え方


- **Rooflineモデルと演算強度：**
  到達可能な性能は、演算性能の上限と、帯域×演算強度の小さい方で決まります。  
  演算強度は、1バイト運ぶ間に何回演算できるかという比率です。  
  演算強度が機械の転換点より低ければメモリ律速、高ければ計算律速と判定できます。


- **Littleの法則：**
  平均の滞在数は、到着率×平均滞在時間に等しくなります。  
  この法則は、同時実行数、キューの長さ、プールのサイズを見積もる基礎になります。  
  第9章と第18章で、プールサイズの決定に再び使います。


- **価値密度：**
  保持による再利用の利益は、回避できたコスト×再利用回数を、保持バイト数×保持時間で割って比べます。  
  キャッシュ、メモ化、プールは、この同じ指標で競わせます。  
  指標が低い保持から先に捨てるのが、メモリ予算の配分の原則です。


- **ベンチマークの落とし穴：**
  ウォームアップなしの初回測定、最適化で消える計算、入力サイズの偏りは、典型的な誤測定です。  
  測定は複数回行い、中央値や分布で見ます。  
  最適化の前後で、条件をそろえた比較だけが証拠になります。


## ハンズオン：自分のマシンの階層レイテンシを実測する


1. サイズの異なる配列を用意し、それぞれについてランダムアクセスの平均時間を測ります。
2. 配列サイズを横軸に取り、時間が階段状に増える境界を探します。
3. 境界の位置から、L1、L2、L3、DRAMのおおよその容量を推定します。
4. 推定した容量を、CPUの仕様値と照合します。


実測した階段が、公開されている階層構造と対応することを確認してください。


## 代償と判断


計測そのものにもコストがあり、測りすぎは開発速度を落とします。  
測るのは、判断が変わり得る箇所だけに絞ります。  
一度作った測定は、再測定できる形で残します。


## 確認


- [ ] Rooflineモデルで、対象がメモリ律速か計算律速か判定できる

- [ ] Littleの法則で同時実行数やプールサイズを見積もれる

- [ ] 価値密度を計算し、保持の採否を説明できる


**演習：** よく使う処理を1つ選び、演算強度を見積もってください。  
その見積もりから、効くはずの最適化と、効かないはずの最適化を1つずつ挙げてください。
