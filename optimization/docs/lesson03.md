# 第3章 プログラミングモデルはメモリの嘘と約束


[目次](../README.md) · [前の章：第2章 計測の作法](./lesson02.md) · [次の章：第4章 レジスタと再計算](./lesson04.md)


**この章で学ぶこと：** プログラミングモデルがメモリについて何を仮定させ、何を隠すのかを読み解き、費用モデルの系譜と評価の4つの問いを使えるようになります。


プログラムの性能は、書いた人の意図だけでなく、言語や枠組みが用意した「メモリの見え方」に決められます。  
この章では、費用モデルの歴史をたどり、第VII部の入口を作ります。


## 考え方


- **RAMモデルの嘘：**
  古典的なアルゴリズム解析は、どのメモリへも同じコストでアクセスできると仮定します。  
  この仮定のおかげで解析は簡単になりますが、現実の階層の差は桁単位です。  
  計算量が同じでも、アクセスの形で実測が大きく変わるのはこのためです。


- **費用モデルの系譜：**
  外部メモリモデルは、ブロック転送の回数で費用を数えます。  
  キャッシュオブリビアスな手法は、階層のパラメータを知らなくても各階層でよく振る舞うことを狙います。  
  PRAM、BSP、LogPは、並列計算と通信の費用をモデル化する試みです。


- **評価の4つの問い：**
  そのモデルで、データの配置を決められるか。  
  移動がいつ、どれだけ起きるか見えるか。  
  寿命と所有が明示されているか。  
  共有と変更がどう規律されるか。  
  この4問で、あらゆる言語と枠組みを同じ物差しで評価できます。


- **メモリモデルという語の二重性：**
  費用の抽象としてのメモリモデルと、並行プログラムの整合性モデルは、別の概念です。  
  ただしどちらも、プログラムがメモリについて何を仮定してよいかという契約である点は共通します。  
  第25章では整合性モデルを、この契約の観点から扱います。


## ハンズオン：同じアルゴリズムを複数の費用モデルで予測する


1. 行列積か大規模なソートを1つ選び、演算回数を数えます。
2. 次に、外部メモリモデルでブロック転送の回数を見積もります。
3. 実測し、どちらの予測が実測に近いか比べます。
4. 予測が外れた箇所について、モデルが捨象した要素を書き出します。


モデルは現実の代用品であり、外れた場所にこそ学びがあります。


## 代償と判断


費用モデルを精密にしすぎると、解析に時間がかかり、移植性も失われます。  
実務では、桁が合う粗いモデルで十分なことがほとんどです。  
モデルの選択自体が、設計判断の一部です。


## 確認


- [ ] RAMモデルの仮定と、その限界を説明できる

- [ ] 4つの問いで、使い慣れた言語を評価できる

- [ ] 費用モデルと整合性モデルの違いを説明できる


**演習：** 普段使う言語や枠組みを1つ選び、4つの問いに短く答えてください。  
その答えから、その言語で性能問題が起きやすい形を予測してください。
