# 第4章 レジスタと再計算


[目次](../README.md) · [前の章：第3章 プログラミングモデルはメモリの嘘と約束](./lesson03.md) · [次の章：第5章 L1・L2・L3キャッシュ](./lesson05.md)


**この章で学ぶこと：** レジスタスピルとリマテリアライゼーションの関係を理解し、保存するか計算し直すかの判断を、最も小さい階層で身に付けます。


メモリ階層の最下段はレジスタです。  
レジスタに載せきれない値は、より遅い階層へこぼれます。  
この章の判断は、後のすべての章で大きなスケールで再登場します。


## 考え方


- **スピルは最速の失敗：**
  同時に生きている値がレジスタ数を超えると、コンパイラは値をスタックへ退避します。  
  退避と復帰は、ただの代入に見えるコードへメモリアクセスを混入させます。  
  変数の数を減らすこと自体が、最適化になる場合があります。


- **リマテリアライゼーションは再計算による節約：**
  安く再計算できる値は、保持せずに使う場所で計算し直します。  
  保持のコストと再計算のコストを比べ、安い方を選ぶのが原則です。  
  これはメモ化の採否とまったく同じ式で判断できます。


- **レジスタ圧と並列度の交換：**
  GPUでは、1スレッドのレジスタ使用量が同時実行できるスレッド数を制限します。  
  値を保持することは、並列度という別の資源を消費します。  
  第14章で、オキュパンシーの問題として再び扱います。


## ハンズオン：変数の寿命を変えてスピルを観察する


1. 中間変数の多い計算を用意し、処理時間を測ります。
2. 中間変数を式の内側へ畳み、寿命の重なりを減らして再測定します。
3. 可能なら生成コードを見て、スタックへの退避が減ったか確認します。
4. 畳みすぎて式が読みにくくなった箇所を記録します。


環境によって生成コードの確認手段は異なります。  
時間の変化だけでも、寿命の重なりの効果は観察できます。


## 代償と判断


再計算は、計算が安いうちは正解ですが、式が重くなると逆転します。  
畳みすぎたコードは保守性が下がります。  
判断は「再計算コスト＜保持コスト」の不等式に戻って行います。


## 確認


- [ ] スピルが起きる条件を説明できる

- [ ] リマテリアライゼーションの採否を不等式で説明できる

- [ ] 保持が並列度を消費する例を挙げられる


**演習：** 自分のコードから中間変数の多い箇所を1つ探してください。  
畳める値と、畳むべきでない値を、再計算コストの観点で仕分けてください。
