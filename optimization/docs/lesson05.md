# 第5章 L1・L2・L3キャッシュ


[目次](../README.md) · [前の章：第4章 レジスタと再計算](./lesson04.md) · [次の章：第6章 プリフェッチとSIMD](./lesson06.md)


**この章で学ぶこと：** キャッシュラインの単位でデータ配置を設計し、AoSとSoAの変換、タイリング、偽共有の回避を、実測で確かめながら使えるようになります。


CPUキャッシュは、最適化の効果が最も劇的に現れる階層です。  
カギは、データが64バイトのキャッシュライン単位で運ばれることです。  
この章の原理は、後のGPU、データベース、CDNでも形を変えて現れます。


## 考え方


- **キャッシュラインと空間局所性：**
  メモリから読むときは、必要な値だけでなく、周辺のバイトも一緒に運ばれます。  
  連続したアクセスはこの仕組みの利益を受け、飛び飛びのアクセスは運んだバイトの大半を捨てます。  
  アクセスの順序をデータの並びに合わせることが、最も基本的な最適化です。


- **AoSとSoA：**
  構造体の配列（AoS）は、1つの要素の全フィールドを同居させます。  
  配列の構造体（SoA）は、フィールドごとに連続させます。  
  一部のフィールドだけを走査する処理では、SoAの方が運ぶバイト数が大幅に減ります。


- **タイリング（ブロッキング）：**
  大きな走査を、キャッシュに収まるブロックへ分割し、ブロック内で再利用します。  
  再利用できる回数が増えるほど、DRAMへ行く回数が減ります。  
  タイリングは、行列計算、画像処理、データのチャンキングと同じ原理です。


- **偽共有：**
  別々のコアが、同じキャッシュライン内の別々の値を更新すると、ラインが行ったり来たりします。  
  データ自体は共有していないのに、運搬の単位のせいで競合します。  
  パディングや配置の分離で回避できます。


## ハンズオン：行列積をタイリングで段階的に速くする


1. 素朴な三重ループの行列積を書き、実行時間を測ります。
2. ループの順序を変え、連続アクセスに近づけて再測定します。
3. 内側の計算をブロックへ分割するタイリングを入れ、ブロックサイズを変えて測ります。
4. 各段階で、運ぶバイト数の見積もりと実測の変化を対応付けます。


ブロックサイズの最適点は環境で異なります。  
最適点を探す過程そのものが、この章の目的です。


## 代償と判断


SoAへの変換は、要素単位の処理を書きにくくします。  
タイリングはコードを複雑にし、端数処理のバグを招きます。  
利益が小さい箇所では、素朴な実装の方が正解です。


## 確認


- [ ] キャッシュライン単位の運搬を前提に、アクセス順序を設計できる

- [ ] AoSとSoAの得失を、処理の形から判断できる

- [ ] タイリングで再利用回数を増やす仕組みを説明できる


**演習：** 自分のコードの走査処理を1つ選び、運んでいるのに使っていないバイトがないか点検してください。  
SoA化かタイリングのどちらが合いそうか、理由と一緒に書いてください。
