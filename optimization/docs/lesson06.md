# 第6章 プリフェッチとSIMD


[目次](../README.md) · [前の章：第5章 L1・L2・L3キャッシュ](./lesson05.md) · [次の章：第7章 TLBと仮想メモリ](./lesson07.md)


**この章で学ぶこと：** 帯域を使い切るためのプリフェッチとベクトル化を、レイテンシ隠蔽と運搬効率の観点で使い分けられるようになります。


キャッシュの仕組みを理解したら、次は帯域の上限まで使う番です。  
プリフェッチは未来のアクセスを先読みし、SIMDは1回の命令で運んだバイトをまとめて処理します。  
どちらも、メモリの遅さを「隠す」「割る」ための技術です。


## 考え方


- **プリフェッチはレイテンシの隠蔽：**
  必要なデータが届くまでの待ち時間は、他の仕事で埋めるか、先に頼んでおくかで隠します。  
  ハードウェアプリフェッチャは規則的なアクセスを自動で先読みします。  
  規則性が崩れる場所では、ソフトウェアプリフェッチが補助になりますが、外すと帯域の無駄遣いになります。


- **SIMDは運搬の割引：**
  ベクトル命令は、1回の読み込みで複数の要素を処理します。  
  ベクトル化できるループは、要素あたりの運搬コストが下がります。  
  ベクトル化を妨げるのは、依存関係、飛び飛びのアクセス、要素ごとの分岐です。


- **ストリーミングとノンテンポラルストア：**
  再利用しない大きな書き込みは、キャッシュを汚さずに直接流す方が有利な場合があります。  
  通常の書き込みは、他のデータのキャッシュを追い出します。  
  再利用の有無で書き込み方を変えるのが要点です。


## ハンズオン：集計ループのベクトル化と先読みを観察する


1. 大きな配列の合計を計算し、実行時間を測ります。
2. コンパイラのベクトル化レポートや最適化オプションで、ベクトル化の成否を確認します。
3. アクセスを連続に保ったまま、分岐を外すなどの書き換えを行い、再測定します。
4. 要素数を変え、帯域の上限に当たるサイズを探します。


帯域の上限に達した後の改善は、この階層では起きません。  
その確認も重要な観察です。


## 代償と判断


プリフェッチの外れは、帯域とエネルギーの浪費です。  
ベクトル化のためのデータ変換は、変換自体の運搬コストと引き換えです。  
上限に近い箇所への追加投資は、効果が頭打ちになります。


## 確認


- [ ] レイテンシを隠す方法と、帯域を上げる方法を区別できる

- [ ] ベクトル化を妨げる要因を3つ挙げられる

- [ ] 再利用しない書き込みの扱いを説明できる


**演習：** 自分のコードの数値ループを1つ選び、ベクトル化できる形かどうか点検してください。  
できない場合は、何が妨げているかを書いてください。
