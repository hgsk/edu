# 第7章 TLBと仮想メモリ


[目次](../README.md) · [前の章：第6章 プリフェッチとSIMD](./lesson06.md) · [次の章：第8章 DRAMとNUMA](./lesson08.md)


**この章で学ぶこと：** アドレス変換のコストを理解し、ページサイズとアクセスの局所性から、ポインタ追跡型の設計がなぜ不利なのかを説明できるようになります。


仮想メモリは、アドレス変換というもう1つの階層を持ち込みます。  
変換結果のキャッシュがTLBであり、ここにも局所性の原理がそのまま当てはまります。


## 考え方


- **ページテーブルウォーク：**
  仮想アドレスから物理アドレスへの変換は、多段のテーブル参照です。  
  TLBに載っていれば高速ですが、外れると複数回のメモリアクセスが発生します。  
  扱うアドレスの範囲が広いほど、TLBミスは増えます。


- **ヒュージページ：**
  大きなページは、1つのTLBエントリで広い範囲を覆います。  
  大きな配列を扱う処理では、変換のミスが減ります。  
  一方で、確保の失敗や断片化、粒度の粗さという代償があります。


- **ポインタ追跡の敗北：**
  連結リストや木をたどる処理は、依存したランダムアクセスの連続です。  
  次のアドレスが分からないため、先読みも並行化もできません。  
  密な配列への変換が効くのは、変換コストと運搬効率の両方が改善するからです。


## ハンズオン：ランダムアクセスと順次アクセスの差を測る


1. 大きな配列を用意し、順次アクセスの時間を測ります。
2. 同じ要素数について、ランダムな順序でのアクセス時間を測ります。
3. 要素のサイズと配列の総量を変え、差がどう変わるか観察します。
4. 結果を、キャッシュとTLBの両方の観点で説明します。


差の出方は環境で異なります。  
どちらの階層が効いているかを切り分けることが目的です。


## 代償と判断


ヒュージページは万能ではなく、用途によっては確保や運用の手間が見合いません。  
密な配列への変換は、挿入や削除の多いデータでは別のコストを生みます。  
局所性の改善は、更新パターンとの兼ね合いで判断します。


## 確認


- [ ] TLBミスが起きる仕組みを説明できる

- [ ] ヒュージページの利益と代償を挙げられる

- [ ] ポインタ追跡が不利な理由を2つの観点で説明できる


**演習：** ポインタでつながったデータ構造を1つ思い浮かべてください。  
それを配列ベースへ変えた場合の利益と代償を書いてください。
