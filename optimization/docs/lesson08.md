# 第8章 DRAMとNUMA


[目次](../README.md) · [前の章：第7章 TLBと仮想メモリ](./lesson07.md) · [次の章：第9章 アロケーションとプール](./lesson09.md)


**この章で学ぶこと：** メモリチャネルとNUMAノードの配置を意識し、スレッドとデータの距離を設計に含められるようになります。


メインメモリは一様なプールではありません。  
チャネルの本数と、CPUソケットごとの距離が、実効性能を決めます。  
この「距離」の感覚は、分散システムの配置設計へそのままつながります。


## 考え方


- **チャネルとインタリーブ：**
  DRAMの帯域は、メモリチャネルの本数で決まります。  
  連続したアドレスは複数チャネルへ分散され、並行に読み書きされます。  
  帯域を使い切るには、複数のチャネルへ均等にアクセスが散る形が必要です。


- **NUMAの距離：**
  複数ソケットのマシンでは、自ノードのメモリと他ノードのメモリで遅延と帯域が異なります。  
  スレッドが動く場所と、データが置かれた場所の組み合わせが性能を決めます。  
  ファーストタッチ方針では、最初に触れたスレッドのノードへページが置かれます。


- **配置は設計事項：**
  スレッドの固定、データの分割、ノード単位の複製は、配置を制御する手段です。  
  共有データを複製すると、帯域と距離は改善し、容量と整合性の管理が増えます。  
  この交換は、分散キャッシュやレプリケーションと同じ形です。


## ハンズオン：スレッド配置とデータ配置の組み合わせを測る


1. メモリ帯域を測る単純なコピー処理を用意します。
2. スレッド数と配置を変えながら、帯域の変化を記録します。
3. 可能なら、データを置くノードとスレッドのノードをずらし、差を観察します。
4. 結果を、チャネル数とノード構成の情報と照合します。


NUMAを持たない環境では、チャネルとスレッド数の関係だけでも観察できます。


## 代償と判断


配置の最適化は、環境依存が強く、移植性を下げます。  
複製による高速化は、容量の消費と更新の伝播を伴います。  
効果が確認できない環境では、配置への投資をやめる判断も必要です。


## 確認


- [ ] チャネル数が帯域を決める仕組みを説明できる

- [ ] NUMAで距離が生まれる理由と、ファーストタッチを説明できる

- [ ] 複製による高速化の代償を挙げられる


**演習：** 自分が使うマシンやサーバーの、チャネル数とノード構成を調べてください。  
その構成で不利になるアクセスパターンを1つ挙げてください。
