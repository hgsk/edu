# 第9章 アロケーションとプール


[目次](../README.md) · [前の章：第8章 DRAMとNUMA](./lesson08.md) · [次の章：第10章 キャッシュに効くデータ構造](./lesson10.md)


**この章で学ぶこと：** 確保と解放のコスト構造を理解し、アリーナとオブジェクトプールの採否とサイズを、同時使用ピークと占有率で決められるようになります。


確保は、見えないメモリ交通です。  
確保と解放のたびに、アロケータの管理情報へのアクセスと、断片化のリスクが発生します。  
プールはその交通を消す技法ですが、予約した容量という別のコストを払います。


## 考え方


- **確保のコストの内訳：**
  確保には、管理情報の更新、空きブロックの探索、スレッド競合の調整が含まれます。  
  解放した領域が再利用できない断片化は、容量の実効値を下げます。  
  短命なオブジェクトの大量確保は、GCのある言語でも追跡と回収の仕事を増やします。


- **アリーナとプール：**
  アリーナは、まとめて確保し、まとめて解放する方式です。  
  オブジェクトプールは、使い終わったインスタンスを破棄せず、リセットして再貸出します。  
  どちらも、個別の確保と解放を、大きな単位の管理へ置き換えます。


- **サイズはピークで決める：**
  プールの適正サイズは、総処理量ではなく同時使用数のピークです。  
  Littleの法則で、到着率と使用時間から同時使用数を見積もれます。  
  占有率が低いプールは、使われないメモリを先食いしているだけです。


- **プールが不利になる条件：**
  構築が安い、再利用の頻度が低い、サイズのばらつきが大きい場合は、プールの管理コストが勝ちます。  
  現代の若い世代向けアロケータでは、短命オブジェクトの確保は意外に安いこともあります。  
  プール化の前に、確保が実際に律速かを測ることが前提です。


## ハンズオン：確保の多い処理をプール化して全体を測る


1. 短命なオブジェクトを大量に作る処理を用意し、時間とメモリ使用量を測ります。
2. 同じ処理をプール版に書き換え、再測定します。
3. プールサイズを変え、占有率と処理時間の関係を記録します。
4. 対象処理だけでなく、プロセス全体のメモリ使用量の変化も記録します。


速くなった場合も遅くなった場合も、その理由を占有率と確保コストで説明できることが目的です。


## 代償と判断


プールは、アイドル時も容量を占有し、他の用途を圧迫します。  
リセット漏れは、状態の混入という深刻なバグを生みます。  
プールしたオブジェクトを貸し出したまま保持されると、枯渇とデッドロックに似た詰まりが起きます。


## 確認


- [ ] 確保のコストの内訳を説明できる

- [ ] プールサイズを同時使用ピークで決める理由を説明できる

- [ ] プールが不利になる条件を3つ挙げられる


**演習：** 自分のコードで確保の頻度が高い箇所を1つ探してください。  
プール化の利益と、占有率の見通しを書いてください。
