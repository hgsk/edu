# 第10章 キャッシュに効くデータ構造


[目次](../README.md) · [前の章：第9章 アロケーションとプール](./lesson09.md) · [次の章：第11章 OSのキャッシュ](./lesson11.md)


**この章で学ぶこと：** データ構造の選択を、計算量だけでなく運搬量と局所性で評価し、ハッシュ表、B木、密な配列、インメモリ圧縮を使い分けられるようになります。


教科書の計算量は、RAMモデルの上での評価です。  
現実のデータ構造の優劣は、アクセスがどれだけキャッシュに優しいかで逆転することがあります。


## 考え方


- **ハッシュ表の局所性：**
  ハッシュ表の検索は平均して定数時間ですが、その1回はランダムアクセスです。  
  エントリが散らばっていると、1件の検索で複数のキャッシュラインを運びます。  
  キーの近くへ値を同居させる設計は、この運搬を減らします。


- **B木が生き残る理由：**
  B木は、ノードをページやキャッシュラインのサイズに合わせ、1回の読み込みで多くのキーを判別します。  
  高さが低く抑えられるため、遅い階層へのアクセス回数が少なくなります。  
  データベースとファイルシステムでB木系が標準であり続けるのは、この運搬効率のためです。


- **密な配列と走査の強さ：**
  小さなデータでは、ソート済み配列の線形走査や二分探索が、ハッシュ表より速いことがあります。  
  運ぶバイト数が少なく、プリフェッチが効くためです。  
  規模とアクセスパターンで、最適な構造は入れ替わります。


- **インメモリ圧縮：**
  辞書符号化やビットパッキングでデータを小さくすると、運搬量と容量が同時に減ります。  
  代償は、伸長と更新のコストです。  
  読み取りが支配的で、値の種類が少ないデータに向きます。


## ハンズオン：検索構造ごとの実測を比べる


1. 同じデータ集合を用意し、ハッシュ表で検索する時間を測ります。
2. ソート済み配列の二分探索と、小さい範囲での線形走査でも測ります。
3. 要素数を段階的に変え、優劣が入れ替わる点を探します。
4. 結果を、運ぶバイト数とアクセス回数の観点で説明します。


入れ替わる点の位置は環境とデータで変わります。  
点が存在すること自体が重要な観察です。


## 代償と判断


局所性のための再配置は、更新コストを上げることがあります。  
圧縮は、すべてのアクセスへ伸長コストを課します。  
構造の選択は、読み書きの比率と一緒に決めます。


## 確認


- [ ] ハッシュ表の「定数時間」の内訳を運搬の観点で説明できる

- [ ] B木が遅い階層に強い理由を説明できる

- [ ] 規模で優劣が入れ替わる例を挙げられる


**演習：** 自分の扱うデータを1つ選び、現在の構造とアクセスパターンを書き出してください。  
運搬の観点で、より合う構造の候補を挙げてください。
