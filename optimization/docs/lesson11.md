# 第11章 OSのキャッシュ


[目次](../README.md) · [前の章：第10章 キャッシュに効くデータ構造](./lesson10.md) · [次の章：第12章 SSDと永続層](./lesson12.md)


**この章で学ぶこと：** ページキャッシュ、mmap、スワップ、ゼロコピーの仕組みを理解し、OSが提供する階層を味方にする設計ができるようになります。


アプリケーションの外側でも、メモリの階層は動いています。  
OSのページキャッシュは、ディスクとメモリの間の巨大なキャッシュです。  
この層を知らないと、二重キャッシュや無駄なコピーを自前で作ってしまいます。


## 考え方


- **ページキャッシュ：**
  ファイルの読み書きは、通常はページキャッシュを経由します。  
  2回目の読み込みが速いのは、ディスクではなくメモリから返るためです。  
  書き込みも、まずキャッシュへ入り、後からディスクへ流されます。


- **mmapとreadの選択：**
  mmapはファイルをメモリとして扱い、必要なページだけを読み込みます。  
  readは明示的にバッファへコピーします。  
  アクセスパターンによって、コピーの回数とページ例外のコストの釣り合いが変わります。


- **スワップとスラッシング：**
  ワーキングセットが物理メモリを超えると、ページの入れ替えが頻発します。  
  この状態では、わずかな容量不足が桁違いの遅さになります。  
  容量の崖は、帯域や遅延の改善では越えられません。


- **ゼロコピー：**
  sendfileやio_uringは、カーネルとユーザ空間の間のコピーを減らします。  
  コピーは帯域とCPUの両方を消費します。  
  データを触らずに運ぶ経路が、最も安い経路です。


## ハンズオン：同じファイルの1回目と2回目の読み込みを測る


1. 大きめのファイルを用意し、読み込み時間を測ります。
2. 続けて同じ読み込みを行い、時間の差を記録します。
3. ファイルサイズを変え、差が出なくなる規模を探します。
4. 結果をページキャッシュの容量と関連付けて説明します。


キャッシュを消去する操作は環境への影響が大きいため、この演習では新規ファイルを使う方法でも構いません。


## 代償と判断


ページキャッシュ頼みの設計は、コールドスタート時の性能を見誤ります。  
自前キャッシュとページキャッシュの二重保持は、容量の無駄です。  
mmapの気軽さは、ページ例外とシグナル処理の複雑さと引き換えです。


## 確認


- [ ] ページキャッシュが読み書きのどこにいるか説明できる

- [ ] mmapとreadの得失をアクセスパターンで判断できる

- [ ] スラッシングが崖になる理由を説明できる


**演習：** 自分のアプリケーションが、OSのキャッシュと二重に保持しているデータがないか点検してください。  
見つけた場合は、どちらか一方へ寄せる案を書いてください。
