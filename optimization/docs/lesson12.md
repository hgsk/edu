# 第12章 SSDと永続層


[目次](../README.md) · [前の章：第11章 OSのキャッシュ](./lesson11.md) · [次の章：第13章 データベース](./lesson13.md)


**この章で学ぶこと：** 順次アクセスとランダムアクセスの非対称、書き込み増幅を理解し、LSM木とB木の選択を運搬量で判断できるようになります。


永続層では、読み書きの非対称がさらに大きくなります。  
SSDはページ単位で読み、ブロック単位で消去します。  
この物理が、データ構造の選択を決めます。


## 考え方


- **順次とランダムの差：**
  SSDでも、ランダムな小さい書き込みは順次書き込みより不利です。  
  内部のガベージコレクションが、余分な書き換えを引き起こすためです。  
  ランダムな更新を順次書き込みへ変換する設計が、永続層の基本戦略です。


- **書き込み増幅：**
  論理的に書いた量より、デバイス内部で実際に書かれる量が大きくなります。  
  この比率が書き込み増幅であり、寿命と性能の両方を悪化させます。  
  上書きの多い設計ほど、増幅の影響を受けます。


- **LSM木とB木：**
  LSM木は、書き込みをまずメモリとログへ集め、後でまとめて整理します。  
  B木は、その場でページを更新します。  
  書き込み中心ならLSM、読み取り中心ならB木が向くのが大まかな目安です。


## ハンズオン：ランダム書き込みと順次書き込みを比べる


1. 同じ総量のデータを、順次に書き込む時間を測ります。
2. 小さな単位でランダムな位置へ書き込む時間を測ります。
3. 書き込み単位のサイズを変え、差の変化を観察します。
4. 結果を、ページとブロックの概念で説明します。


測定は小さな一時ファイルで行い、実データには触れないでください。


## 代償と判断


LSM木は、読み取りの増幅とコンパクションの負荷と引き換えに書き込みを安くします。  
順次化のためのバッファリングは、耐久性の窓を広げます。  
永続層の最適化は、性能と耐久性の両方で会計します。


## 確認


- [ ] 書き込み増幅が起きる仕組みを説明できる

- [ ] LSM木とB木の得失を読み書き比で判断できる

- [ ] ランダム更新を順次へ変換する設計例を挙げられる


**演習：** 自分のシステムの永続化を1つ選び、書き込みパターンを書き出してください。  
増幅を減らす変更案を1つ挙げてください。
