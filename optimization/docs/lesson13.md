# 第13章 データベース


[目次](../README.md) · [前の章：第12章 SSDと永続層](./lesson12.md) · [次の章：第14章 VRAMとHBM](./lesson14.md)


**この章で学ぶこと：** インデックスを「メモリと書き込みで買う検索」として会計し、バッファプール、マテリアライズドビュー、プッシュダウンを同じ原理で扱えるようになります。


データベースは、メモリ階層の原理が最も体系化された分野です。  
インデックス、バッファプール、マテリアライズドビューは、それぞれキャッシュとメモ化の姿です。


## 考え方


- **インデックスの会計：**
  インデックスは、検索の読み取りを減らす代わりに、容量と書き込み時の更新を買います。  
  効果は、選択率とアクセス頻度で決まります。  
  使われないインデックスは、書き込み税だけを払い続ける資産です。


- **バッファプール：**
  データベースは、ディスク上のページをメモリへ保持する専用キャッシュを持ちます。  
  ワーキングセットがバッファプールに収まるかどうかが、性能の分かれ目です。  
  OSのページキャッシュとの二重管理は、古典的な論点です。


- **マテリアライズドビューはDB規模のメモ化：**
  集計結果を保存し、再計算を避ける仕組みは、関数のメモ化と同じ構造です。  
  鮮度の管理と更新コストが、メモ化の無効化問題とそのまま対応します。  
  採否は、再計算コスト、再利用回数、保持サイズで判断します。


- **プッシュダウンは計算をデータへ運ぶこと：**
  フィルタや集計を、データのある場所で実行すれば、運ぶ量が減ります。  
  述語プッシュダウンや射影の削減は、その具体例です。  
  第21章のデータグラビティと同じ判断です。


## ハンズオン：インデックス追加の利益と代償を会計する


1. テーブルと検索クエリを用意し、実行計画と時間を測ります。
2. インデックスを追加し、実行計画と時間の変化を記録します。
3. 書き込みの時間と、インデックスの容量も測ります。
4. 読み取り回数の見通しを使い、何回読めば元が取れるか計算します。


実行計画の読み方が、この章の中心的な技能です。  
数値と計画をセットで記録してください。


## 代償と判断


インデックスの追加は、読み取りの最適化と書き込みの劣化を同時に起こします。  
マテリアライズドビューは、鮮度の遅れを受容する設計判断を含みます。  
バッファプールの拡大は、同じマシンの他のメモリ用途を圧迫します。


## 確認


- [ ] インデックスの利益と代償を会計できる

- [ ] マテリアライズドビューとメモ化の対応を説明できる

- [ ] プッシュダウンが運搬を減らす仕組みを説明できる


**演習：** 自分の使うデータベースのインデックスを1つ選び、会計をしてください。  
読み取り頻度の実測がない場合は、どうやって調べるかも書いてください。
