# 第15章 ML推論と学習


[目次](../README.md) · [前の章：第14章 VRAMとHBM](./lesson14.md) · [次の章：第16章 運ぶバイトを減らす](./lesson16.md)


**この章で学ぶこと：** 量子化、KVキャッシュ、勾配チェックポイント、FlashAttention、バッチングを、すべてデータ移動の削減として統一的に説明できるようになります。


大規模モデルの計算は、メモリの壁の最前線です。  
この分野の主要な最適化は、ほぼすべて「運ぶバイト数を減らす」ことに帰着します。


## 考え方


- **量子化はバイト数の削減：**
  重みと活性を低い精度で表すと、運ぶ量と容量が同時に減ります。  
  推論のデコードは帯域律速のため、精度を半分にすると理論上の速度上限が大きく上がります。  
  代償は、数値誤差と精度評価の手間です。


- **KVキャッシュは容量の律速：**
  推論では、過去のトークンのキーと値を保持し続けます。  
  保持量は、層数、次元、系列長、バッチサイズの積で増えます。  
  文脈を長くするほど、容量と帯域の両方が圧迫されます。


- **勾配チェックポイントはメモ化の拒否：**
  学習では、中間結果を保持せず、逆伝播のときに再計算します。  
  容量を計算で買うこの選択は、メモリが高価だという前提の最も有名な実例です。  
  どの層で区切るかが、容量と再計算量の設計になります。


- **FlashAttentionとバッチング：**
  FlashAttentionは、注意の計算をタイル化し、中間行列をHBMへ書かずに済ませます。  
  バッチングは、重みの読み込みを複数リクエストで割ることで演算強度を上げます。  
  どちらも、運搬の単位と再利用回数を変える最適化です。


## ハンズオン：モデルのメモリ会計と速度上限を見積もる


1. モデルのパラメータ数から、重みのバイト数を複数の精度で計算します。
2. 想定する系列長とバッチサイズで、KVキャッシュの容量を計算します。
3. 帯域の公称値から、デコード速度の理論上限を見積もります。
4. 量子化、バッチング、チェックポイントのうち、どの次元に効く施策かを仕分けます。


実測環境がなくても、会計だけで施策の当たり外れをかなり絞れます。


## 代償と判断


量子化は、評価なしに適用すると品質事故になります。  
バッチングは、スループットと引き換えにレイテンシを悪化させます。  
チェックポイントは、容量の代わりに計算時間と電力を払います。


## 確認


- [ ] KVキャッシュの容量を見積もれる

- [ ] デコードが帯域律速になる理由を説明できる

- [ ] チェックポイントを「メモ化の拒否」として説明できる


**演習：** 関心のあるモデルを1つ選び、重みとKVキャッシュの会計をしてください。  
容量が不足する場合の打ち手を、次元の仕分けと一緒に挙げてください。
