# 第18章 プールと配置の分散版


[目次](../README.md) · [前の章：第17章 分散キャッシュ](./lesson17.md) · [次の章：第19章 フロントエンド](./lesson19.md)


**この章で学ぶこと：** コネクションプールをネットワーク規模のオブジェクトプールとして理解し、シャーディング、レプリケーション、シャッフルのコストを配置の観点で判断できるようになります。


第9章のプールと配置の議論は、ネットワーク規模でも繰り返します。  
接続は、確保の重いオブジェクトです。  
データの配置は、NUMAの距離の問題の拡大版です。


## 考え方


- **コネクションプール：**
  接続の確立には、ハンドシェイクと認証という固定費がかかります。  
  プールはこの固定費を避けるための再利用機構です。  
  サイズの決め方はオブジェクトプールと同じで、同時使用のピークと占有率で判断します。


- **シャーディングは配置の分割：**
  データを分割して持つと、各ノードの容量と帯域の負担が減ります。  
  代償は、分割をまたぐクエリと、再配置の難しさです。  
  分割キーの選択が、将来のアクセスの形を決めます。


- **レプリケーションは複製の交換：**
  コピーを持つと、読み取りの距離と帯域は改善します。  
  代償は、容量と、更新を全コピーへ伝える運搬です。  
  読み書き比が高いほど、複製は有利になります。


- **シャッフルは最悪の移動：**
  分散処理で全ノードが相互にデータを送り合う段階は、総運搬量が最大になります。  
  結合や集約の前の局所的な事前集計は、シャッフル量を減らす定石です。  
  分散処理の性能は、多くの場合シャッフルの設計で決まります。


## ハンズオン：プールサイズと待ちを測る


1. 接続を使う処理を用意し、接続を毎回張る版の時間を測ります。
2. プール版を作り、プールサイズを変えて時間と待ちの発生を記録します。
3. 同時実行数を変え、占有率と性能の関係を観察します。
4. 結果をLittleの法則の見積もりと照合します。


最適なサイズは、源泉側の上限でも決まります。  
自側だけでなく相手の容量も会計に入れてください。


## 代償と判断


プールを大きくしすぎると、源泉側の接続上限とメモリを圧迫します。  
シャーディングは、後からの分割キー変更が高くつきます。  
複製は、整合性の問題を必ず連れてきます。


## 確認


- [ ] コネクションプールとオブジェクトプールの対応を説明できる

- [ ] シャーディングの代償を2つ挙げられる

- [ ] シャッフル量を減らす方法を説明できる


**演習：** 自分のシステムの接続や配置を1つ選び、同時使用ピークと複製の有無を点検してください。
