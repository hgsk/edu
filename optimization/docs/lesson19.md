# 第19章 フロントエンド


[目次](../README.md) · [前の章：第18章 プールと配置の分散版](./lesson18.md) · [次の章：第20章 CDN](./lesson20.md)


**この章で学ぶこと：** クライアントもメモリ階層の一段として捉え、転送量、パースと保持のコスト、遅延読み込みを設計できるようになります。


ブラウザやアプリのクライアントは、階層の最もユーザに近い一段です。  
ここでは、転送量そのものと、受け取った後の保持がコストになります。


## 考え方


- **転送とパースの二重のコスト：**
  スクリプトや画像は、運ぶコストに加えて、解釈と展開のコストがかかります。  
  圧縮されたサイズと、メモリ上で展開されたサイズは別物です。  
  大きなバンドルは、ダウンロードと実行開始の両方を遅くします。


- **分割と遅延読み込み：**
  必要なときに必要な分だけ運ぶ設計は、初期コストを下げます。  
  代償は、後から必要になった場面での待ち時間です。  
  利用パターンの予測精度が、この設計の成否を決めます。


- **状態の持ちすぎ：**
  クライアントに保持する状態は、メモリと、破棄や同期の複雑さを消費します。  
  サーバから取り直せるものを、複雑な仕組みで保持し続ける必要は必ずしもありません。  
  保持の採否は、価値密度で判断できます。


## ハンズオン：ページの転送量とメモリを測る


1. 対象のページや画面を選び、開発者ツールで転送量を記録します。
2. リソース種別ごとに、サイズと読み込みの順序を確認します。
3. メモリの使用量も記録し、保持している状態の内訳を推定します。
4. 削減候補を、転送と保持の両面から挙げます。


数値は端末と回線で変わります。  
絶対値より、内訳の偏りを見ることが目的です。


## 代償と判断


遅延読み込みは、操作の応答性を損なう場面を作ります。  
状態の削減は、オフライン対応や復帰の速さと引き換えです。  
削減のしすぎは、再取得の往復を増やします。


## 確認


- [ ] 転送コストと保持コストを区別できる

- [ ] 分割と遅延読み込みの得失を説明できる

- [ ] クライアント側の保持を価値密度で評価できる


**演習：** 自分の関わる画面を1つ選び、転送量の内訳を調べてください。  
最も偏りの大きい項目について、削減案を書いてください。
