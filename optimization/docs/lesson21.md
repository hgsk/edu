# 第21章 エッジコンピューティングとデータグラビティ


[目次](../README.md) · [前の章：第20章 CDN](./lesson20.md) · [次の章：第22章 クラウドの会計](./lesson22.md)


**この章で学ぶこと：** 計算をデータへ運ぶか、データを計算へ運ぶかの判断を、移動量、頻度、整合性の観点で下せるようになります。


データには重力があります。  
大きなデータは、置かれた場所の近くへ計算と利用を引き寄せます。  
この章では、配置の最終判断を扱います。


## 考え方


- **移動の会計による比較：**
  データを計算へ運ぶコストは、サイズ×頻度で見積もれます。  
  計算をデータへ運ぶコストは、プログラムの配布と、結果だけを戻す運搬です。  
  結果が入力より十分に小さいなら、計算を動かす方が有利です。


- **データグラビティ：**
  データが蓄積するほど、移すコストが prohibitive になり、周辺に処理が集まります。  
  最初の配置の選択が、後年の選択肢を狭めます。  
  出口のコストを、入口の時点で会計に入れることが重要です。


- **整合性のコスト：**
  複数拠点で書き込みを受けると、整合性の調整という通信が発生します。  
  強い整合性は、距離のある拠点間ではレイテンシとして跳ね返ります。  
  要件を弱めることができる場所を探すのが、設計の仕事です。


## ハンズオン：3案の配置を移動量で比べる


1. 具体的な処理を1つ選び、データ量と利用頻度を仮置きします。
2. データを集約する案、計算を分散する案、複製して近づける案の3案を作ります。
3. 各案について、月あたりの移動バイト数と、整合性の論点を書き出します。
4. 仮置きの数値を変え、結論が入れ替わる条件を探します。


結論そのものより、入れ替わる条件を特定できたことが成果です。


## 代償と判断


計算の分散は、運用対象と監視の複雑さを増やします。  
複製は、移動の削減と引き換えに容量と整合性を消費します。  
配置の決定は、移行コストのために半ば不可逆です。


## 確認


- [ ] 移動の会計で配置案を比較できる

- [ ] データグラビティが選択肢を狭める過程を説明できる

- [ ] 強い整合性がレイテンシになる理由を説明できる


**演習：** 自分のシステムのデータ配置を1つ取り上げ、出口のコストを見積もってください。
