# 第22章 クラウドの会計


[目次](../README.md) · [前の章：第21章 エッジコンピューティングとデータグラビティ](./lesson21.md) · [次の章：第23章 命令型とオブジェクト指向](./lesson23.md)


**この章で学ぶこと：** クラウドの料金をバイト単価の請求書として読み、容量、帯域、転送、リクエストを一つの予算で最適化できるようになります。


クラウドでは、メモリが高価だという仮説が、請求書の形で現れます。  
料金表は、階層ごとの単価表として読めます。  
設計の判断を、そのまま金額で評価できるのがこの層の特徴です。


## 考え方


- **egressは最も分かりやすい単価：**
  クラウドの外へ出す転送には、バイト単位の料金がかかります。  
  内部の転送と外部の転送で単価が違うため、配置がそのまま費用になります。  
  CDNのヒット率は、この層では直接の費用削減です。


- **容量とリクエストの料金：**
  ストレージは、容量×時間で課金されます。  
  APIリクエストにも回数の料金があり、小さな操作の頻発が高くつく設計があります。  
  保持の価値密度は、この層では金額で計算できます。


- **階層化とライフサイクル：**
  アクセス頻度に応じて、データを安い階層へ移すライフサイクル設計が用意されています。  
  移行自体にも費用と時間がかかります。  
  頻度の実測なしに階層化すると、取り出しの遅さと料金で逆効果になります。


## ハンズオン：1か月分の費用を見積もって再現する


1. 対象システムの、容量、転送量、リクエスト数の月次見積もりを作ります。
2. 料金表を引き、各項目の金額を計算します。
3. 最も大きい項目について、設計変更でどれだけ減るか試算します。
4. 試算の前提が崩れる条件も書きます。


料金は変わります。  
単価の出典と日付を記録し、結論は前提つきで述べてください。


## 代償と判断


費用の最適化は、性能や運用の最適化と衝突することがあります。  
安い階層への移行は、取り出しの遅延と手数料を伴います。  
見積もりの精度が低い段階では、大きな設計変更より計測が先です。


## 確認


- [ ] 料金表を階層の単価表として読める

- [ ] egressと配置の関係を金額で説明できる

- [ ] 保持の価値密度を金額で計算できる


**演習：** 自分のシステムの月次見積もりを1項目だけ作ってください。  
その項目を減らす設計変更と、その代償を書いてください。
