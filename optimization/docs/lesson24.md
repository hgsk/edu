# 第24章 関数型、イミュータブル、遅延評価


[目次](../README.md) · [前の章：第23章 命令型とオブジェクト指向](./lesson23.md) · [次の章：第25章 所有権とマネージドモデル](./lesson25.md)


**この章で学ぶこと：** 永続データ構造と構造共有、遅延評価のthunk、参照透過性が可能にする最適化を、保持と運搬の観点で評価できるようになります。


関数型のモデルは、値を変えないことで、共有と並行を安全にします。  
その安全性は、保持とコピーの設計と引き換えです。  
遅延評価は、言語に組み込まれたメモ化と見ることができます。


## 考え方


- **永続データ構造と構造共有：**
  変更のたびに全体をコピーするのではなく、変わらない部分を共有します。  
  共有のおかげでコピーは安くなりますが、構造はポインタの多い形になります。  
  走査の局所性との交換が、このモデルの中心的な論点です。


- **thunkは組み込みのメモ化：**
  遅延評価では、計算は要求されるまで遅延され、結果は保持されて再利用されます。  
  これは関数のメモ化と同じ構造です。  
  要求されない計算を保持し続けると、スペースリークと呼ばれるメモリの滞留が起きます。


- **参照透過性が開く最適化：**
  結果が入力だけで決まる関数は、メモ化、並列化、再配置が安全に行えます。  
  副作用のある計算は、これらの最適化の前提を崩します。  
  純粋さは、美学ではなく最適化の適用条件です。


- **イミュータブルの代償：**
  変更のたびの経路コピーは、更新の多い処理では割当量を増やします。  
  バッチ化された変更や、一時的な可変領域の併用が実務の落とし所になります。  
  モデルの純粋さと、局所的な例外の管理が設計課題です。


## ハンズオン：遅延評価の滞留を再現する


1. 大きなリストへの畳み込みを、遅延評価の言語か、遅延を模した実装で用意します。
2. メモリ使用量の推移を観察し、滞留が起きる条件を特定します。
3. 正格な畳み込みへ変え、推移の変化を記録します。
4. 結果を、thunkの保持という観点で説明します。


対象の言語がない場合は、遅延を模した小さな実装でも観察できます。


## 代償と判断


構造共有は、保持期間を延ばしやすく、大きな構造の一部を掴んだまま全体を保持する事故が起きます。  
正格化は、無限構造や短絡評価の利点を失わせます。  
純粋さの徹底は、現実の入出力との境界設計を必要とします。


## 確認


- [ ] 構造共有の利益と代償を説明できる

- [ ] thunkとメモ化の対応を説明できる

- [ ] 参照透過性が最適化の前提になる理由を説明できる


**演習：** 自分の使う言語の遅延や共有の仕組みを1つ調べ、滞留が起きそうな使い方を書いてください。
