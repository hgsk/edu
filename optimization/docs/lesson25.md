# 第25章 所有権とマネージドモデル


[目次](../README.md) · [前の章：第24章 関数型、イミュータブル、遅延評価](./lesson24.md) · [次の章：第26章 宣言型と、計算とスケジュールの分離](./lesson26.md)


**この章で学ぶこと：** 所有権と借用、GC、参照カウントを寿命と移動の観点で比較し、整合性モデルと同期のコストを運搬として理解できるようになります。


メモリ管理のモデルは、寿命を誰が決めるかの違いです。  
その違いは、実行時の交通の形として現れます。  
この章では、言語のメモリモデルという語の2つの意味を両方扱います。


## 考え方


- **所有権と借用：**
  Rustのモデルは、値の所有者と借用をコンパイル時に決め、実行時の管理をほぼ消します。  
  寿命とエイリアスが明示されるため、最適化器も大胆に動けます。  
  代償は、表現できない形の共有構造と、学習コストです。


- **GCの仕組み：**
  GCは、到達可能性をたどって不要な領域を回収します。  
  コピー方式のGCは、生きているオブジェクトを移動させます。  
  管理が自動である代わり、回収のタイミングと移動は予測しにくくなります。


- **参照カウント：**
  参照の数の増減を数え、ゼロで解放します。  
  解放は決定的ですが、カウントの更新自体が交通になり、循環参照に弱いです。  
  原子的なカウントは、並行環境では競合のコストも持ちます。


- **整合性モデルと同期：**
  並行プログラムのメモリモデルは、他スレッドの書き込みがいつ見えるかの契約です。  
  同期操作は、キャッシュコヒーレンスの交通として実体化します。  
  ロックやアトミックの多用は、見えない移動を買う行為です。


## ハンズオン：同じ処理の割当量を2つのモデルで比べる


1. 小さな処理を、GCのある言語で実装し、割当量と時間を測ります。
2. 所有権を明示する言語か、手動管理の実装で同じ処理を書き、再測定します。
3. 割当の発生箇所を数え、モデルの違いと対応付けます。
4. 書きやすさと、誤りの種類の違いも記録します。


言語そのものの優劣を競うのではなく、交通の形の違いを観察することが目的です。


## 代償と判断


所有権の明示は、プログラムの書き方を強く制約します。  
GCの予測しにくさは、レイテンシの厳しい用途で問題になります。  
同期の削減は、正しさの検証負担を増やします。


## 確認


- [ ] 3つの管理モデルの交通の形を説明できる

- [ ] GCの移動が起きる理由を説明できる

- [ ] 同期がコヒーレンスの交通になることを説明できる


**演習：** 自分の主言語のメモリ管理モデルについて、実行時に発生している交通を書き出してください。
