# 第28章 統一採否基準


[目次](../README.md) · [前の章：第27章 並列と分散のモデル](./lesson27.md) · [次の章：第29章 アンチパターン集](./lesson29.md)


**この章で学ぶこと：** キャッシュ、メモ化、オブジェクトプールを一つの予算と価値密度で評価し、採用、不採用、配分の決定を根拠つきで下せるようになります。


終部では、これまでの全技法を一つの判定へ統合します。  
技法ごとに語られてきた採否を、共通の会計で裁きます。  
この章が、本講座の実務的な結論です。


## 考え方


- **判定の式：**
  利益は、回避できた回数×回避できたコストから、保持と管理のコストを引いたものです。  
  取得コストが回避対象以上なら、再利用率が高くても採用しません。  
  この式は、レジスタからCDNまで全階層で同じ形をしています。


- **価値密度による配分：**
  総メモリ予算の中で、価値密度の高い保持から順に配分します。  
  技法ごと、層ごとに別々の予算を持つと、合計で破綻します。  
  予算は全体で1つ持ち、配分を定期的に見直します。


- **無効化の設計：**
  保持の正しさは、無効化の設計で決まります。  
  TTL、明示通知、バージョン付けには、それぞれ鮮度と複雑さの交換があります。  
  無効化を設計できない保持は、採用できません。


- **キャッシュしないという決定：**
  源泉が十分に速い、再利用が読めない、保持が全体を圧迫する場合は、保持しないことが最適です。  
  不採用の記録は、将来の再検討の材料になります。  
  決定と根拠を残すこと自体が、設計の成果物です。


## ハンズオン：3技法の候補を評価シートで裁く


1. キャッシュ、メモ化、プールの候補を1つずつ用意します。
2. 各候補について、回避コスト、再利用回数、保持バイト数、保持時間を書き出します。
3. 価値密度を計算し、総予算の中で配分の順序を決めます。
4. 不採用にした候補について、理由と再検討の条件を記録します。


数値が実測できない項目は、見積もりの根拠を明記してください。  
根拠の明記が、判定の再現性を担保します。


## 代償と判断


統一基準は、局所的な都合を切り捨てることがあります。  
見積もりの不確かさが大きい候補は、試験導入と測定の段階を挟みます。  
基準の運用自体にも、手間というコストがあります。


## 確認


- [ ] 判定の式で、保持の採否を説明できる

- [ ] 価値密度で配分の順序を決められる

- [ ] 不採用の決定を、再検討条件つきで記録できる


**演習：** 自分のシステムの保持をすべて棚卸ししてください。  
価値密度の低い順に3つ挙げ、縮小か廃止の案を書いてください。
