# 第30章 総合演習


[目次](../README.md) · [前の章：第29章 アンチパターン集](./lesson29.md)


**この章で学ぶこと：** 遅いシステムを題材に、律速の特定から、予算配分、施策の実施、効果の会計までを通しで実行し、説明できるようになります。


最後の章は、これまでの全章を1つの仕事として実行します。  
題材は、複数階層に問題を持つシステムです。  
速くすることではなく、会計の正しさが評価の中心です。


## 考え方


- **進め方：**
  まず計測し、律速を次元ごとに特定します。  
  次に総メモリ予算を決め、価値密度で施策へ配分します。  
  施策は1つずつ入れ、その都度全体を再測定します。


- **成果物：**
  律速の特定根拠となった測定結果を提出します。  
  採用した施策と、不採用にした施策の両方の記録を提出します。  
  移動バイト数の前後比較と、残った律速の説明を提出します。


- **評価の観点：**
  速度の改善幅そのものは、評価の一部にすぎません。  
  見積もりと実測の差を説明できているかを重視します。  
  代償の申告が正直であることも、評価の対象です。


## ハンズオン：全階層を通して最適化する


1. 題材システムのベースラインを、全階層について測定します。
2. 律速の仮説を立て、総メモリ予算と配分案を作ります。
3. 配分案に従って施策を実施し、各段階で再測定します。
4. 最後に、移動バイト数の会計と、残課題をまとめます。


途中で仮説が外れたら、その記録も成果物に含めてください。  
外れた記録は、会計の正しさの証拠です。


## 代償と判断


総合演習は、時間配分の設計が成否を分けます。  
全階層を触ろうとして、測定が浅くなるのが典型的な失敗です。  
深く掘る階層を、仮説の段階で選ぶことが重要です。


## 確認


- [ ] 律速の特定から会計までを、根拠つきで説明できる

- [ ] 不採用の記録を含めて、判断の過程を示せる

- [ ] 残った律速と次の打ち手を説明できる


**演習：** この演習の題材にしたい、自分の遅いシステムを1つ挙げてください。  
最初に測るべき3項目を、第2章の道具で設計してください。
