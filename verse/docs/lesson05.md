# 第5単元 失敗可能式とoption


[目次](../README.md) · [前の単元：第4単元 デバイス連携](./lesson04.md) · [次の単元：第6単元 エフェクトシステム](./lesson06.md)


**この単元で学ぶこと：** `<decides>` の付いた関数の呼び方、失敗コンテキスト、`option` 型の扱いを説明できるようになります。


## 失敗を例外ではなく仕組みにする


Verseには例外（try/catch）がありません。  
代わりに、「失敗するかもしれない計算」を言語の仕組みとして表します。


- 失敗しうる関数には、効果として `<decides>` が付きます。

- 失敗しうる関数の呼び出しは、丸括弧ではなく角括弧 `[ ]` で書きます。

- 失敗しうる呼び出しは、失敗を受け止める場所（失敗コンテキスト）の中でだけ書けます。


代表的な失敗コンテキストは、`if` の条件と、`for` の条件です。  
失敗すると、そのブロック全体が静かにスキップされます。  
エラーで止まるのではなく、「その場合は何も起きない」が基本の動きです。


## コードを読む


```verse
    GreetFirstPlayer() : void =
        if (FirstPlayer := GetPlayspace().GetPlayers()[0]):
            Print("先頭のプレイヤーがいます")
```


`GetPlayers()` はプレイヤーの配列を返します。  
`[0]` の添字アクセスは失敗可能です。  
プレイヤーが一人もいなければ失敗し、`if` 全体がスキップされます。  
配列の添字だけでなく、マップの検索や、`agent` からキャラクターを取る操作も失敗可能として定義されています。

```verse
    CheckCharacter(Agent : agent) : void =
        if (FortChar := Agent.GetFortCharacter[]):
            Print("キャラクターはスポーン済みです")
        else:
            Print("まだスポーンしていません")
```


成功した前提で一直線に書き、失敗した場合の分岐は `else` に寄せるのがVerseの読みやすい形です。  
C++のように「全部チェックしてから進む」書き方をすると、かえって読みにくくなります。

なお、この例の `GetFortCharacter` を使うには、ファイル先頭の `using` に `/Fortnite.com/Characters` を追加してください。  
標準の3つだけでは、実機検証で「Unknown member `GetFortCharacter` in `agent`」というエラーになりました。


## option型


「値があるかもしれないし、ないかもしれない」ことを型で表すのが `option` です。  
`?int` と書くと「`int` があるかもしれない」という型になります。

```verse
    FindBonus(Score : int) : ?int =
        if (Score >= 100):
            option{Score}
        else:
            false
```


- 値がある場合は `option{値}` で作ります。

- 値がない場合は `false` を返します。

- 取り出す側は、失敗コンテキストの中で `?` を使って開きます。

```verse
    UseBonus(Score : int) : void =
        BonusOption := FindBonus(Score)
        if (Bonus := BonusOption?):
            Print("ボーナスは {Bonus} です")
```


`option` を返す関数の結果は、いったん変数で受けてから `?` で開きます。  
呼び出しを `if` の条件へ直接書くと、ロールバックできない呼び出しとしてコンパイルエラーになります（実機検証で確認しました）。  
「ある前提で進み、なければ抜ける」という考え方は、どちらの形でも同じです。


💡 **ヒント：**

> 角括弧 `[ ]` には2つの役割があります。  
> 型パラメータ（`[]int` のような型の表記）と、失敗可能な呼び出しです。  
> 式の中で名前の直後に来る `[ ]` は、失敗可能な呼び出しだと思ってください。


## 確認


- [ ] 例外の代わりに失敗可能式を使う理由を説明できる

- [ ] 添字アクセス `[0]` が失敗する場面を挙げられる

- [ ] `?int` と `option{値}`、`false` の関係を説明できる


**演習：** プレイヤーの配列から先頭のプレイヤーを取り、いる場合だけ挨拶を表示し、いない場合は「プレイヤーはまだいません」と表示する関数を書いてください。
