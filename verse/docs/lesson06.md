# 第6単元 エフェクトシステム


[目次](../README.md) · [前の単元：第5単元 失敗可能式とoption](./lesson05.md) · [次の単元：第7単元 非同期処理](./lesson07.md)


**この単元で学ぶこと：** 関数の宣言に付く効果（エフェクト）の注釈を読み、「その関数が何をしてよいか」から呼び出し可能な場所を判断できるようになります。


## エフェクトは型の一部です


Verseでは、関数のシグネチャに「何をする関数か」が含まれます。  
C++の `const` や `noexcept` を、はるかに広く強くしたものだと思ってください。  
よく見る4つを先に覚えます。


- **`<transacts>`：** 状態を読み書きできる効果です。
  失敗コンテキストの中で失敗すると、その関数の書き込みはすべて巻き戻されます。
  「読み取り専用」という意味ではありません。

- **`<varies>`：** 呼ぶたびに結果が変わりえる効果です。
  `var` の読み取りなど、現在の状態に依存する関数に付きます。

- **`<suspends>`：** 途中で中断して、外部の出来事を待つことがあります。
  非同期処理の印です。

- **`<decides>`：** 失敗することがある効果です。
  呼び出しは `[ ]` で、失敗コンテキストの中だけに書けます。


## シグネチャの読み方


```verse
    GetScore()<transacts> : int =
        FixedScore

    GetCurrentScore()<varies> : int =
        CurrentScore

    WaitForStart()<suspends> : void =
        StartSignal.Await()

    ParseLane(Text : string)<decides> : int =
        LaneByName[Text]
```


読むときは、名前と引数だけでなく、効果まで含めて1つの宣言として読みます。  
たとえば `<suspends>` の付いた関数は、中断しない文脈からは呼べません。  
「呼べない」というコンパイルエラーが出たら、まず呼び出し側と定義側の効果の対応を見ます。


## 効果が呼び出しを制限する理由


効果の制限は、安全のための設計です。


- `<transacts>` と保証された関数は、失敗したときに書き込みを巻き戻せます。
  保証されるのは「読み取り専用」ではなく、「失敗したら書き込みが無かったことになる」点です。

- `<suspends>` の境界が分かると、「ここで処理が他へ移るかもしれない場所」が読み手に伝わります。

- `<decides>` の境界が分かると、失敗したときにどこまでが取り消されるかが追えます。


💡 **ヒント：**

> 初期に一番よく出るエラーは、「`<suspends>` な関数を、そうでない関数から呼んでいる」というものです。  
> 呼び出し側の関数へも `<suspends>` を付けるか、次単元の `spawn{ }` で別タスクとして投げるか、どちらかで解決します。


## overrideと効果


`OnBegin<override>()<suspends>` のように、指定子は複数並びます。  
土台の関数を上書きするときは、土台側の効果と矛盾しないように付ける必要があります。  
公式のデバイスの関数は効果まで含めて仕様なので、サンプルのシグネチャはそのまま写すのが安全です。


## 確認


- [ ] `<transacts>` と `<varies>` の違いを、状態との関係で説明できる

- [ ] `<suspends>` な関数を呼べない文脈がある理由を説明できる

- [ ] シグネチャを読むときに、効果まで含めて読む習慣がついた


**演習：** 次の3つの関数に、ふさわしい効果を付けてください。  
(1) 固定の制限時間を返す関数。  
(2) `var` の現在スコアを返す関数。  
(3) ボタンが押されるまで待つ関数。
