# 第12単元 他言語からの移行


[目次](../README.md) · [前の単元：第11単元 Scene Graph入門](./lesson11.md)


**この単元で学ぶこと：** C++とPythonの知識のうち、Verseへそのまま持ち込めるものと、手放すべきものを区別できるようになります。


## C++から来た人へ


持ち込めるものは、静的型付けの感覚、クラスで設計する考え方、型パラメータの読み方です。  
一方で、構文と概念の違いは小さくありません。


同じ処理を並べて見ます。

```cpp
// C++
int Add(int A, int B)
{
    int Result = A + B;
    return Result;
}
```

```verse
# Verse
Add(A : int, B : int) : int =
    Result := A + B
    Result
```


構文の主な違いです。


- 型は名前の後ろに書きます。セミコロンと波括弧はありません。

- `=` は関数の本体に使い、定義は `:=`、再代入は `set` です。

- 型パラメータは `<>` ではなく `[ ]` です。`<>` は効果や指定子に使います。

- ポインタ、参照、三項演算子、`switch` はありません。

- コメントは `#`、論理演算は `and`、`or`、`not` です。


概念の主な違いです。


- **エラーの扱い：** 例外やエラーコードの代わりに、失敗可能式（第5単元）を使います。

- **効果：** `const` より広い範囲を、効果（第6単元）で宣言します。

- **状態：** 共有した値を書き換え続ける設計から、不変を基本にして `var` を絞る設計へ移ります。

- **非同期：** スレッドの代わりに、協調的な中断（第7単元）を使います。


## Pythonから来た人へ


見た目は一番近い相手です。  
インデント、`#` コメント、`and` / `or` / `not`、文字列への埋め込みは、ほぼそのまま読めます。  
ただし意味論は別物です。


- **型：** Pythonの型ヒントは任意ですが、Verseの型はコンパイル時にすべて検査されます。動的な属性追加やダックタイピングはありません。

- **コレクション：** Pythonのリストはその場で書き換えますが、Verseの配列とマップは不変です。

- **エラー：** `try` / `except` はありません。失敗可能式と `option` で扱います。

- **実行環境：** ファイルやOSのAPIはなく、すべてエンジンのAPI経由で、サーバー権威のシミュレーションの中で動きます。


## 血統で見る近さ


字面の近さとは別に、設計の血統で近い言語もあります。


- **F#、Scala、Nim：** 「インデント、静的型付け、式指向」の組み合わせが近く、字面の感覚も近い言語です。

- **Haskell：** 設計の源流です。関数の本体を `=` で書く形、失敗を型で表す考え方は、この系統から来ています。

- **Curry：** Verseと同じ関数論理言語で、失敗と非決定性の扱いが血統的に一番近い相手です。


Verseは「MLやHaskellの系統の言語を、Python風の見た目に整えて、ゲーム用に出したもの」と捉えると、多くの判断が当たります。


## 移行でつまずく3つの癖


- **継承で設計する癖：** VerseやScene Graphでは、合成で組み立てる方向が基本です。

- **状態を書き換え続ける癖：** 不変を基本にし、`var` は状態の置き場だけに絞ります。

- **エラーを戻り値コードで返す癖：** 失敗可能式と `option` に置き換えます。


この3つを手放せた時点で、Verseはだいたい書けるようになります。  
あとは公式ドキュメントのAPIを引く作業です。

> 移行の近道は、書きたい処理を「他の言語ならどう書くか」から先に考えることです。
